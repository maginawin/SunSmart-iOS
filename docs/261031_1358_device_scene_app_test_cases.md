# Device Scene App 测试用例

日期：2026-10-31。审查基线：`feat/device-scene-261028`，`c1a7bd2ac59eaf8333254e686e089679f3f4c764` 相对父提交。

**本轮修复：R2～R5 已完成 App 修复，相关隔离回归及 SunSmart 本地 workspace 的 generic iOS Debug 构建通过。真机、实灯和服务器验收仍未执行，见第 5 节。** 第 1、4 节保留初次审查时的证据；R1 不属于本轮实施范围，其原始 SDK 快照不代表当前依赖状态。

本表按最终实现对应的后续确认方案验收：Custom 的 CREATE 先建立空场景；Select devices 的关闭/DONE 只返回 Settings 并保留内存草稿；Settings 的 DONE 持久化后直接进入 Sync device(s)，不再走旧 SEND / CONFIRM & SAVE 流程；单设备及 Groups 参数弹层支持实时控制，Devices 分类批量编辑不实时控制。早期需求文档与这些时序不一致时，以后续确认的 [DONE 方案](261030_1614_scene_done_sync_plan.md)、[选择页方案](261031_0944_scene_select_devices_plan.md)、[组实时控制方案](261030_1530_scene_group_live_control_plan.md)及本提交为本次测试口径。

## 2. 环境、数据和记录方式

### 测试准备

- 主测 SunSmart；共享文件也进入 Archipelago、SLG Sync Plus、SylSmart、Lumineux、HSmart。正式 SDK 集成后，构建所有受影响 scheme；代表品牌做完整功能，其余品牌做创建、资源、文案和基本同步冒烟。
- 准备 owner、editor、visitor；第二台测试手机用于分享、云端往返与跨手机状态验证。记录 App commit、品牌、系统版本、SDK revision、Space 和设备固件版本。
- 使用隔离测试 Site/Space，避免影响真实照明。涉及紧急模式只在受控测试设备上执行，不触发实际消防系统。
- G1：A（色温灯）、B（单色调光灯）、X（不选入场景的对照灯）。G2：C（继电器）、D（与 A 色温范围不同的灯）。E 为未分组色温灯。F 为先加入场景、再断电的既有成员；N 为从未加入的离线设备。另准备空组 G0、不支持场景的在线设备。
- 基准设备场景 SD：A=ON/30%/3000K、B=ON/80%、C=OFF、E=ON/50%/5000K。各值如超出实机范围，改用该型号范围内两个明显不同值并记录。X 始终是“不应受影响”的对照。
- 另备组场景 SG、一个可用实体开关、支持 Scheduler 的设备；容量边界用专用设备，勿挤占日常配置。多 Element、EFC、继电器及扩展 CCT 用例需要相应型号，缺设备记录阻塞，不记通过。

### 记录与判定

- 测试优先级：**P0** 为发版前必跑主链路/数据安全，**P1** 为边界和关联回归，**P2** 为扩展展示覆盖；不是 Review 缺陷等级。
- 每个编号记录：结果（未测/通过/失败/阻塞）、执行人、时间、实际结果及截图/脱敏日志。以下默认全部“未测”。
- 分别记录 App 配置落盘、设备 Store/Delete/日程命令确认、实灯变化、云端回读结果；不能用页面成功提示替代后三者。
- 观察命令时记录目标地址、命令类型、场景号和成功/失败，不记录 Device Key、凭据或完整云端原始载荷。DEBUG 可用 `[SceneSync]` 的 stage、scene、address、pending；抓包只用于测试设备。
- 本表中断电、断线、退出重启均需在指定步骤执行。SQLite/投影失败、迟到回调、坏 JSON 等需要工程协助的用例，优先使用现有夹具，不修改服务器、固件或其运行配置来制造故障。
