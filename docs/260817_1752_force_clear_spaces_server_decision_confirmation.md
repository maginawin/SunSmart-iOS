# Force Clear Spaces 服务器决策确认

## 结论

本次回复在产品流程层面完整且可行，已经解决上一轮提出的核心冲突：独立 Force Clear 使用原子清空接口；Delete 使用增强后的 `gatewayDelete` 一次性完成网关删除与全部关联空间解绑，不扩展成两个连续请求。

在服务器接口定义完成前暂不开始 App 开发，也不展开最终开发计划。

## 已确认决策

### 独立 Force Clear Spaces

- 服务器提供按 gatewayId 原子清空全部 Associated Spaces 的专用接口。
- App 不再逐条调用单 Space 解绑接口，因此不存在客户端多请求导致的部分成功问题。
- Owner 可以执行；非 Owner 必须对全部关联空间拥有 Editor 权限。
- 30 秒是整个操作的最大等待上限；明确的网络错误或服务器失败可以提前结束。
- 成功 Toast 使用正确文案：`All associated spaces cleared from server`。

### Delete / Force Delete

- 服务器增强现有 `gatewayDelete`：一次请求内同时删除 Gateway 并解绑全部 Associated Spaces。
- App 不应在 `gatewayDelete` 后再调用独立清空接口。
- `gatewayDelete` 必须成功后，App 才能继续蓝牙删除流程。
- 蓝牙删除失败并进入 FORCE DELETE 时，App 必须持有已确认的服务器删除成功状态；只有该状态成立，才允许提交本地永久删除和 Mesh Node 移除，并最终确认强制删除成功。
- `gatewayDelete` 失败或超时，App 不得把网关视为已从服务器删除，也不应进入可确认成功的 FORCE DELETE 路径。

## 对服务器接口的必要约束

服务器安排接口时建议明确以下合同，避免 App 开发阶段再次产生歧义。

### 原子性

- 独立清空接口必须在单个事务中清空执行时该 gatewayId 的全部关联空间。
- `gatewayDelete` 必须在单个事务中完成 Gateway 删除与全部关联空间解绑。
- `gatewayDelete` 中任一步失败时，整个事务失败并回滚；不能出现 Gateway 已删除但部分关联仍存在，或关联已清空但 Gateway 删除失败。

### 幂等性

- Gateway 已无关联空间时，独立清空接口仍返回成功。
- 对同一 gatewayId 重复调用清空接口应安全并返回成功。
- 需要明确 Gateway 已不存在时独立清空接口的返回语义。推荐按幂等成功处理，或返回 App 可明确识别的固定业务码。
- 重复调用 `gatewayDelete` 的语义也应固定，避免网络超时后重试产生不确定结果。

### 并发语义

- 清空接口应按执行事务时服务器的当前关联关系清空全部空间，不应要求 App 上传一份可能过期的 spaceId 列表。
- 需要防止清空与新关联请求并发时产生清空后又残留旧关联的竞态；建议服务器通过事务锁、版本号或等价机制保证最终状态可判定。

### 权限

- 服务器必须作为最终权限裁决者，不能只依赖 App 预检。
- Owner 允许执行。
- Editor 只有在对该 Gateway 当前关联的全部 Spaces 都有编辑权限时才允许执行。
- 权限校验与清空/删除必须处于同一事务边界或使用同一权威快照，避免校验后权限或关联关系发生变化。

### 返回结果

- 明确 HTTP 状态、业务 `code`、`isSuccess` 与错误码约定。
- 成功响应必须能够明确证明整个原子操作已经提交，不能只表示“请求已接收”。
- 若采用异步任务，需返回 requestId，并提供最终状态查询接口；App 的 30 秒应等待最终提交结果，而不是只等待受理响应。
- 建议成功响应至少返回 gatewayId，以及清空/解绑完成的明确状态；可选返回清除数量用于日志诊断。

### 超时与重试

- App 在 30 秒无最终结果时按失败展示，但服务器可能稍后完成，因此接口必须幂等。
- 需要定义超时后的查询或重试策略，避免 App 本地显示失败、服务器随后成功所造成的状态分歧。
- 下一次进入 Gateway 页面时，App 仍应以服务器数据重新校正 Associated Spaces。

## 后续 App 流程边界

服务器合同确定后，后续开发计划应按两条独立状态链设计：

### 独立 Force Clear

确认弹窗 → 原子清空接口 → 服务器最终成功 → 清空本地 GatewayModel 与编辑副本 → 刷新 Site 拓扑 → 成功 Toast。

任何明确失败或 30 秒无最终结果：不修改本地，显示失败 Toast。

### Delete / Force Delete

Delete 确认 → 原子 `gatewayDelete` → 服务器最终成功 → 蓝牙 Reset。

- 蓝牙 Reset 成功：完成本地删除。
- 蓝牙 Reset 失败：展示 FORCE DELETE；此时服务器成功状态已经成立。
- 点击 FORCE DELETE：无需再次调用清空接口，直接提交本地永久删除；只有本地提交完成后才确认 Force Delete 成功。
- `gatewayDelete` 失败或超时：中断流程，不开始蓝牙 Reset，不确认删除成功。

## 仍需服务器提供的信息

1. 独立原子清空接口的 method、path、请求参数和完整响应示例。
2. `gatewayDelete` 增强后的事务保证与成功响应定义。
3. 两个接口的权限错误、Gateway 不存在、并发冲突、服务器异常等业务码。
4. 是否同步返回最终结果；如果异步，提供 requestId、查询接口和终态定义。
5. 超时后查询或幂等重试规则。

以上信息到齐后，再基于最终服务器合同更新 App 开发计划。
