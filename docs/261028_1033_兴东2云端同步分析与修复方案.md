## 完整行为链

1. 进入空间请求 get/spaceprops，HTTP 200。导入先处理元数据，再执行旧基线、Profile 和 membership 核对。日志出现 `stage=cloudMembership error=-2002 reason=none`，导入保留本地配置。
2. 本地版本高于最后确认版本，needUploadCloud 仍为 true。进入页面触发自动同步；resumeUpload 在没有 pending submission 的情况下先 GET 基线。
3. 第二次 GET 同样成功，但日志停在 `baselineReconciliation / membership / -2002`。此段日志没有配置 POST，因此“无法确认云端同步”在这里实际表示上传前核对失败，而非已经上传但确认响应丢失。
4. Share 在 dirty 状态下先安排云端同步，不能直接生成分享。Space 退出也会立即同步；失败回调在 exitSyncSpace=true 时展示统一的“Failed to save...”提示。用户提供的日志没有 Share/退出操作本身，提示来源由代码定位，具体触发顺序未做现场复现。
5. 列表 Sync 按钮点击后立即把图标隐藏；showSyncCloudError 在任务 wait/inProgress 时也返回 nil。图标消失不代表版本已确认。失败回调理论上会刷新列表并恢复错误；用户所见持续隐藏的具体时序还需任务结束日志/人工验收确认。

## 已复现缺陷及关联影响

`SiteDeviceOwnershipReconciler` 可在同 Site 的其他 Space 存在同 MAC 更新配网实例时，经身份、代次和可写权限核对后清理旧实例。清理通过 DevicePermanentDeletionContext 持久化 replacement 证明，完成后记录 cleaned/completedTimestamp，并使旧 Space 需要上传。

`readbackRemovals` 会返回最后确认版本之后完成的 replacement 清理。`reconcileCloudMembership` 同时用于上传前和上传后，却无条件拒绝“GET 中还包含这些已清理旧实例”。因此合法顺序“本地清理 → 上传删除后的配置 → GET 确认云端已删除”被变成“云端先删除 → 才允许上传”。

隔离复现：建立两台设备的已确认基线；保留云端不变；本地移除一台、推进版本、记录 cleaned replacement；无 pending receipt。生产 reconcileCloudMembership 返回 false，生产 resumeUpload 也返回 failure，复现发生在首次 POST 之前。普通未修改基线对照允许继续。

影响范围包括 Space 自动/手动同步、Site 内空间批量上传、分享前同步，以及复用上传流程的解绑/退出路径。旧 Space 未上传时其他手机仍可能读取旧设备及旧计划目标；这不证明实体设备同时属于两个网络，也不代表应向旧设备发送 Reset。

另外两项相关问题：

- 多个 membership guard 只返回 false，无细分原因；调用方最终显示相同 -2002。当前导出只有基线存在标志、配置指纹和未完成清理标志，无法闭合现场根因。
- SpaceViewController 的同步完成/失败代理未先按当前 Space 过滤任务；若同一管理器同时处理其他空间，exitSyncSpace=true 时其他任务回调也可能引发退出或失败弹窗。属于代码可见风险，现场日志没有证明本次发生。

历史恢复代次取消问题仅用于提醒检查生命周期。本次日志没有代次切换证据，不把它认定为此次根因，也不自动扩大到重构整个同步队列。

## 建议实施范围

1. **区分上传前基线核对和上传后回读。** 复用现有恢复状态、删除日志和身份校验。无 pending submission 时，云端仍匹配已确认基线且本地存在有效完成清理证明，应允许提交当前完整配置；云端已经删掉旧实例时，保留现有合法子集协调。已有 accepted submission 的回读仍要求云端满足该提交及清理后的配置，不提前推进确认时间。
2. **保护一致性与存量恢复。** 同时核对旧实例身份、网络、权限、相关拓扑、Timed/Scheduler 数据及本地版本。拒绝同地址换身份、未知新增、无证明删除和无关远端变更；不能仅凭数量变少放行。成功确认后才清理 journal；失败、取消、重启保持 dirty 和证据。已有 cleaned replacement 记录可直接重试，无需要求重新删除设备。证据不足进入明确复核流程，不静默覆盖云端。
3. **补诊断并统一显示。** 给 membership 失败分支稳定 reason；记录版本、集合数量、清理类型和命中数量，不记录密钥。调试导出补充脱敏恢复/删除摘要，区分 pending 与 completed。列表由任务状态驱动 pending/失败/成功，不靠点击时隐藏图标表示完成；只在对应版本回读确认后显示已同步。退出提示保留具体失败原因；新用户文案补齐英文与简体中文。
4. **过滤页面回调。** 只让包含当前 Site/Space 的任务改变本页退出和错误状态，覆盖单 Space、Site 批量同步及无关任务。
5. **修复现有回归脚本的接口漂移。** check_space_recovery_receipts.py 对 HDBConfigurationStore.deviceConfiguration 的文本边界仍是旧签名，当前生产签名新增 sensorTypes，导致原脚本夹具编译失败。只更新对应测试边界，不改变 HDB 业务逻辑。

本次仅 App。当前证据不要求 SDK API、固件或服务器修改；服务器保持现有完整配置保存/GET 契约，实际联调验证仍需确认写后结果。不会直接上传所提供的调试 JSON、强制导入 305 台云端快照、清空基线或伪造同步成功。

## 新方案：接受同版本仅减少 Nodes（2026-10-28，尚未实施）

建议采纳用户提出的行为：同一 Space 的完整云端响应中，时间戳及其他属性保持不变，仅删除了部分原有 Nodes，App 自动删除本地对应旧实例。这意味着缺失节点在旧 Space 中以云端成员列表为准；不能继续强制上传本机旧列表把它们补回。

服务端使用 node.uuid 作为主键、设备重置后加入另一 Space 会使旧 Space 丢失节点，是用户本轮确认的服务端事实；本轮未独立读取服务器代码或数据库。不再重新调查 Device UUID 赋值链，也不修改 UUID 的 Mesh 身份语义。

### 当前代码与新方案的差异

- `ImportData.swift` 的 `shouldApplyServerData` 已包含“同时间戳、汇总或模型/计划变化、且本地不待上传”时导入的分支，因此不能把问题简化为时间戳相等一律跳过。
- 当前导入会先调用 `preserveLocalMembershipIfNeeded`。该方法将同版本、声明数量大于实际 Nodes 的响应识别为不完整数据，并持久保存 `prefersLocalMembership`；已有该标记时持续保留本地。`reconcileCloudMembership` 也会因该标记直接跳过清理。这与新方案直接冲突。
- 现有 `SpaceCloudNodeRemovalPolicy` 已按 UUID、主地址和 Device Key 指纹比较配网实例；`DevicePermanentDeletionContext.removeCloudInstances` 已有本地删除、检查点、日志、持久回读和恢复流程，可直接作为执行基础。
- 现有 `configurationData` 只保留部分逻辑配置，不包含所有 Node 属性、Group 名称及完整 Scene/Switch 等数据。仅依赖这份投影相等，不能声称满足用户要求的“其他属性都不变”。
- 现有成员协调会清理本地 Timed nodeSlots 后与远端原始 Timed 数据比较；若服务器只删除 Nodes、保留原有 nodeSlots，就可能报 `timedConfigurationChanged`。需要在本次删除集合限定内，对比较两端执行相同的引用清理，再比较其余内容。

### 判定规则

1. 响应确属当前账号、Site、Space 和网络，来自现有完整 Space 查询；权限变更、强制导入和恢复状态仍先执行原有检查。缺少 `nodes`、`null` 或解析失败不能当作空列表。显式 `nodes: []` 是合法的全部移除候选。
2. 以同版本的可信快照比较。干净本地可使用已确认本地快照；本地有待上传修改时，使用最后确认快照或明确已接受的提交快照，不能拿最新本地列表当旧基线。远端时间戳须等于所选快照时间戳；更旧响应不使用此例外，较新响应按已有同步规则处理。
3. 云端 Nodes 必须是该快照 Nodes 的严格子集。按 UUID 对齐后核对主地址、Device Key、Elements 及保留节点的其他属性；不能只比较数量或 UUID。新增节点、实例替换、保留节点内容改变均不属于本次例外。JSON 对象键顺序不构成差异；只对已明确无序的集合做顺序规范化。
4. 比较快照中 `nodes` 之外的完整业务属性，包括时间戳、Group/Profile、Scene、Schedule、Switch、spaceData/HDB。复用已定义的旧格式默认值兼容；不能以只检查部分字段的投影取代“其余不变”。接口独有的权限/在线元数据沿现有独立流程核对，不作为新增可忽略字段的理由。`deviceCount` 等服务端汇总仍可能保留旧值，不能因此拒绝已证实的纯移除；本地最终计数从实际存活节点重算。
5. 原始响应可以仍含被移除节点的旧引用。先确认变化仅来自 Nodes 删除，再为执行和后续回读统一投影清理这些旧引用；仅允许该删除集合引起的引用变化，其他配置差异仍走原有冲突流程。
6. 删除目标为可信快照中有、当前云端中无、且本地仍匹配的旧配网实例。本地未上传新增节点保留；相同 UUID 已在本地重新入网或地址被新实例复用时，不沿用旧删除意图。无法证明旧实例身份时不自动删除。

例如，已确认快照为 A/B/C，本地离线新增 D，云端同版本返回 A/C：本地结果应为 A/C/D，继续保留 D 及其他本地编辑的待上传状态。不能直接用 A/C 覆盖整个本地 Space。

### 最小完整修改范围

1. **共享判定。** 在现有 Space 同步安全逻辑中补齐纯移除判断，覆盖 Site 内 Space 导入、单 Space GET、上传前协调和上传后回读。普通导入与正在上传的提交分别使用对应基线，保持原有提交 ID、代次和取消校验。
2. **本机优先状态迁移。** 命中新规则时不再自动建立或继续依赖 `prefersLocalMembership`。已有标记、`localReplacementVersion` 与 accepted receipt 的 `permitsCloudRemoval` 必须一起处理，先完成证据核对和恢复记录持久化，再切换策略。不能仅删除一个 guard，也不能清空所有空间的恢复状态。旧标记下已经重写过的云端成员基线可能缺少待删旧设备，需核对已确认快照/提交记录；`last-complete-export.json` 也可能是未确认导出，不能仅凭文件存在就当作已确认版本。
3. **复用本地清理。** 复用 cloudRemoval journal 和 `removeCloudInstances`，按旧实例清理本地 Node、Scene 地址、计划 nodeAddresses/nodeSlots、Group 传感器引用、Trigger Zone/路径、HDB 设备、开关代理及相关分发记录。更新设备计数和页面缓存。采用已有云端清理路径，不向已迁走设备发送 Mesh Reset；保留其新 Space 的 Site 级网关关联。
4. **落库与后续同步。** 保持检查点、prepared/removed/cleaned 状态和数据库回读；失败或退出后可继续，重复响应幂等。本地引用清理会形成需要上传的新版本，复用现有清理后上传机制，只提交清理后的数据。云端时间戳不变是接纳该响应的条件，不意味着后续本地修复必须冻结时间戳。回执只确认对应提交，不清除更晚的本地编辑。
5. **调整旧回归。** 原有“同版本少节点必须保留本机”和“部分回读成功但本机继续保留缺失节点”的用例，需要按新业务规则重新划分。保留本轮无关的任务回调过滤、列表状态和诊断改进。

本次必要修改限定 App 共享逻辑及相关测试，预计无需新增 SDK API、资源或品牌条件。正常只读角色的权威导入仍按原路径执行，不能因写入协调使用可上传权限门槛而让列表停留旧数据；需在回归中确认。

- 本地编辑：离线新增节点、保留节点改名/Profile 编辑、同 UUID 重新入网及地址复用；只处理能够证明的旧实例，不丢失本地新增和其他编辑。
- 应拒绝本例外：少节点同时新增节点、保留节点属性/密钥/Elements 改变、其他配置改变、较旧响应、缺字段或损坏数据。拒绝例外后继续原有冲突/恢复语义。
- 状态恢复：已有本机优先标记、旧 accepted/unknown receipt、旧 cleaned journal、写入失败、取消/重启、并发新提交、重复 GET。清理落库与基线推进失败都必须可重试，不能先清空证据。
- 实施后选择现有 receipt、membership、删除清理、Timed/拓扑相关回归；确认本地 SDK 映射后构建一次 SunSmart generic iOS Debug。隔离夹具中的网络/数据库替身不能代替真实落库与服务端验收。
- 最短人工验收：设备由旧 Space 重置加入另一 Space 后，在旧 Space 执行同步；旧设备及引用消失，其他本地编辑保留；退出重进和重启后数量稳定，Share 不再因同版本纯移除受阻，新 Space 的设备及网关关联仍在。

本方案依赖服务端 GET 返回完整当前成员列表。若接口也可能返回无法标识的临时部分结果，同一 JSON 无法同时证明真实迁移和漏返回；这是采用该兼容语义的证据边界。另外，旧客户端或并发上传能否把已迁移 UUID 再写回旧 Space，属于服务端写入规则，App 清理不能保证其他客户端停止写回。该项由服务器团队核对，未纳入本次 App 修改，也不以本地编译代替联调结论。

本轮仅完成当前工作树源码核对与本文档更新，未修改业务代码、测试或 SDK，未构建和运行设备。上面的验证项目均是实施后的待验证项。


## 确认方案后的实施结果（2026-10-28）

已在当前 `fix/llh-sync-261028` 工作树完成 App 实现。开始时已有此前同步修复的未提交改动；保留了任务回调过滤、列表状态、诊断和本地 handoff 修复。本轮没有提交、推送或修改 SDK、固件、服务器。

### 最终行为

- Site/Space 导入、上传前 GET、accepted POST 后回读共用同版本纯移除判定。时间戳匹配所选已确认/已接受提交版本，云端 Nodes 为严格子集，并核对剩余节点全部属性及完整 App 导出业务字段的指纹；服务端 `deviceCount` 不作为成员真值。字段指纹不保存原始凭据；权限、网关在线状态与请求身份沿原有流程核对。
- 新上传回执、确认基线和导入基线持久保存可选完整字段指纹，兼容旧恢复文件。旧记录只能从版本与实例匹配的导出快照，或没有待上传编辑的已确认本地快照补证据。证据不足进入已有配置复核流程，不静默删除或无限显示普通同步失败。
- 命中规则后保存证据和检查点，再移除旧本机优先标记并执行 cloudRemoval 清理。accepted receipt 中由于旧偏好禁止删除的标记同步迁移；未知 POST 结果、未接受提交仍不允许推导删除。节点减少不再自动建立永久本机优先，也不再通过“本机继续保留缺失节点”的部分 GET 路径确认上传。
- 删除只作用于已证明的旧实例。离线新增节点和剩余设备/Group 的本地修改保留；同 UUID 已换地址重新入网、相同地址 Device Key 改变或地址被其他节点复用时拒绝旧实例清理。增加换地址保护，是为了避免 UUID 级 HDB 引用清理影响新实例。
- 复用现有持久删除及拓扑事务，清理 Scene、计划地址/nodeSlots、Trigger Zone、路径、HDB、Group 传感器、开关代理等引用并刷新数量和缓存；不发送 Mesh Reset，保留新 Space 的网关关联。失败保留日志，重复 GET 不重复生成删除意图。
- 服务端仍携带旧节点引用时，两端只投影清理已证明删除的引用。连续多次云端删除会累计已完成清理；本地 handoff 中尚在云端的实例不会提前从云端基线抹去。清理产生的新本地版本沿现有上传与回读确认流程继续，不清除随后发生的编辑。
- 本地 Timed 已从 v1 升级到 v2 但尚未上传时，在原降级拦截前核对纯移除；命中后只清理设备，保留本地 v2 配置。访客继续走原有权威导入，不由写入协调流程发送修复上传。
