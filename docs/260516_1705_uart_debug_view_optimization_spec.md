# UART Debug 页面展示优化规格

## 背景

当前 Debug 页面已支持连接设备后判断 UART 服务，并进入 UART 消息页面展示接收消息。真机测试后确认基础链路可用，但消息展示密度偏低，且缺少调试时常用的时间、自动滚动控制、暂停接收、清除消息和文本过滤能力。

本次优化只调整 App 侧 UART 消息页面，不新增发送、预设、导入导出、持久化日志，也不新增日志级别分类筛选。

## 目标

- 提升 UART 消息页面的信息密度。
- 每条消息都显示精确接收时间。
- 允许用户控制是否自动跟随最新消息。
- 允许用户暂停接收 UART 消息，并在恢复后只接收新的消息。
- 允许用户确认后清除页面中已缓存的消息。
- 允许用户按文本内容过滤已接收消息。

## 非目标

- 不解析或展示 Info、Debug、Error 等日志级别。
- 不缓存 Stop 期间的 UART 消息。
- 不做消息发送功能。
- 不做日志持久化、导出、导入。
- 不修改设备端 UART 协议。

## 页面结构

UART 页面保持现有导航标题，导航栏下方新增固定功能区，消息列表位于功能区下方。

UI 原型中的文字使用英文：

```text
Navigation Bar
┌────────────────────────────────────┐
│ UART Messages                      │
├────────────────────────────────────┤
│ Auto | Manual  [ Stop ] [ Clear ]  │
│ Filter messages                    │
├────────────────────────────────────┤
│ 2026-05-16 17:05:12.123            │
│ [ UART message text ]              │
│                                    │
│ 2026-05-16 17:05:13.456            │
│ [ Another UART message ]           │
└────────────────────────────────────┘
```

## 功能设计

### 消息展示

- 每条 UART 消息都展示 Datetime。
- Datetime 使用格式：`yyyy-MM-dd HH:mm:ss.SSS`。
- 不再沿用“同一分钟只显示一次时间”的展示策略。
- 消息气泡圆角从当前较大圆角调整为 `9`。
- 消息之间的视觉间距调整为约 `8`，减少列表中的额外空白。
- 保持从旧到新的顺序展示。

### Auto / Manual

- 默认模式为 `Auto`。
- `Auto` 模式下，收到新消息并且新消息符合当前过滤条件时，列表自动滚动到最新可见消息。
- `Manual` 模式下，收到新消息只刷新列表，不主动滚动。
- 用户切换回 `Auto` 后，列表应滚动到当前最新可见消息。

### Stop / Start

- 默认状态为 `Stop` 按钮，表示当前正在接收消息。
- 点击 `Stop` 后停止 UART notification 接收，按钮变为 `Start`。
- Stop 期间设备发出的 UART 消息不保存、不缓存、不展示。
- 点击 `Start` 后重新开启 UART notification，只接收恢复之后的新消息。
- 如果重新开启失败，展示现有 UART 不可用提示，并保持页面可返回。

### Clear

- `Clear` 按钮显示在 `Stop` / `Start` 按钮右侧。
- 点击 `Clear` 后弹窗确认是否清除消息。
- 弹窗操作为 `Cancel` 和 `Clear`。
- 点击 `Cancel` 不清除任何消息，页面状态保持不变。
- 点击 `Clear` 清除页面内已缓存的全部 UART 消息，并刷新列表为空。
- `Clear` 不改变当前接收状态：接收中仍保持接收，Stop 状态仍保持停止。
- `Clear` 不清除过滤文本，也不切换 `Auto` / `Manual` 模式。

### 文字过滤

- 功能区提供文本输入框。
- 用户输入内容前后的空格会被忽略。
- 用户输入内容中间的空格保留。
- 空字符串表示不过滤。
- 匹配时忽略大小写。
- 过滤仅影响展示，不删除已接收消息。
- 修改过滤条件后立即刷新列表。
- 在 `Auto` 模式下，修改过滤条件后如果存在可见消息，应滚动到最新可见消息。

## 数据流

- `DebugBluetoothSession` 继续负责启动和停止 SDK 暴露的 UART notification。
- `SpaceDebugUARTViewController` 保存当前页面生命周期内已接收的消息数组。
- 页面根据当前过滤文本计算可见消息数组。
- Stop 时调用现有停止接收能力，不额外保留 Stop 期间的消息。
- Start 时调用现有开始接收能力，沿用现有错误处理路径。
- Clear 时清空 `SpaceDebugUARTViewController` 中的消息数组，不影响 SDK notification 状态。

## 可行性结论

这些优化都可以在现有 App 层完成，不需要引入新的库，也不需要修改设备端协议。Stop / Start 可以复用当前 `startUARTMessages` 与 `stopUARTMessages` 的能力；Clear、文本过滤、Datetime 展示、Auto / Manual 滚动属于页面状态和列表展示逻辑。

需要注意的是，Stop 通过关闭 UART notification 实现，设备端是否仍持续发送由设备决定；App 侧保证 Stop 期间不会保存或展示这些消息。

## 验证范围

- 构建验证：至少验证 `SunSmart` Debug iOS 真机构建。
- 回归验证：如涉及 target 配置或共享代码，再验证 `Archipelago`、`SylSmart`、`SLG Sync Plus`。
- 手动验证：
  - 默认进入页面为 `Auto`，新消息自动滚动到底部。
  - 切换 `Manual` 后，新消息不会自动滚动。
  - 点击 `Stop` 后停止展示新消息，按钮变为 `Start`。
  - 点击 `Start` 后继续展示恢复之后的新消息。
  - 点击 `Clear` 后选择 `Cancel`，已有消息保持不变。
  - 点击 `Clear` 后选择 `Clear`，已有消息被清空。
  - `Clear` 后当前接收状态、过滤文本和滚动模式保持不变。
  - 输入过滤文本后只展示包含该文本的消息。
  - 过滤忽略大小写并忽略输入前后空格。
  - 每条消息都显示 `yyyy-MM-dd HH:mm:ss.SSS` 格式时间。
