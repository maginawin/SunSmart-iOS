# 网关在线删除：服务器优先，取消强制删除分支

- 日期：2026-09-16。
- 状态：已按此方案完成开发；实现与验证记录见 `260916_1200_gateway_delete_implementation.md`。
- 替代方案：`260916_1103_gateway_local_first_delete_evaluation.md` 中的本地优先／异步云删除方案，以及 `260916_1045_gateway_delete_scope_analysis_plan.md` 中保留 FORCE DELETE 的处理方式。

## 1. 最新产品规则

Owner 和 Editor 发起网关删除时，手机均必须能访问服务器。

用户完成现有 Delete → Continue 确认后：先从服务器删除网关，服务器明确成功后，按蓝牙可通信状态决定是否尝试 Reset，随后完成本地删除。取消 FORCE DELETE 弹窗和对应的第二次选择。

网关蓝牙未就绪，或尝试 Reset 后仍无法确认成功，都完成本地删除，并提示用户重新添加前手动重置硬件。

采用这一规则后，不再需要为正常删除增加离线云删除队列，也不需要等待用户在 Reset 失败后再次批准本地删除。

## 2. 完整流程

1. **手机联网检查**：Owner、Editor 一致；无互联网时提示并停止，不请求服务器、不发送 Reset、不删除本地。
2. **权限与本地上下文预检**：保留既有权限规则；Editor 校验服务器当前关联 Spaces 的编辑权限，服务器执行最终权限判断。提前捕获 Site、主网络、目标 Node 和网关身份，避免后续 Node 被移除后丢失清理范围。
3. **服务器删除**：调用 `/sitespace/sapce/gateway/delete`。复用既有幂等合同、30 秒请求上限，以及防止普通注册／更新与删除并发的保护。
4. **服务器失败／超时**：停止，不发 Reset，不主动删除本地，显示服务器删除失败。若请求超时，不能断言服务器一定未执行；后续可通过幂等接口重试确认结果。
5. **服务器明确成功**：保存待本地收尾状态，然后重新检查目标网关的蓝牙 Mesh Proxy 是否就绪。
6. **蓝牙已就绪**：通过现有 SDK 发送 `ConfigNodeReset`，等待成功或有限超时；复用现有单节点约 10 秒的等待上限。
7. **蓝牙未就绪**：不启动自动重连或无限等待，直接转本地清理，并标记需手动重置。
8. **Reset 未确认成功**：包括超时、断连、发送失败，同样转本地清理并标记需手动重置；不弹 FORCE DELETE。
9. **本地清理完成**：移除目标 GatewayModel、Node 和必要的业务扩展数据，关闭详情并刷新 Site。Reset 已确认成功时显示普通完成反馈；其他情况显示手动重置说明。

服务器成功后即使手机互联网中断，仍继续蓝牙尝试和本地收尾，不回滚服务器结果，也不再次要求互联网连接。成功结果只在本地持久化清理确认完成后展示。

## 3. “在线”必须区分两件事

| 状态 | 用途 |
| --- | --- |
| 手机可访问服务器 | 开始删除的前置条件，Owner／Editor 一致 |
| 手机到目标网关的蓝牙 Mesh Proxy 已就绪 | 是否可以尝试发送 Reset |
| 网关 WiFi／4G／MQTT 云端在线 | 不用作蓝牙 Reset 的可发送条件 |

现有详情页 `isGatewayProxyReady` 来源于 `GatewayDetailProxyConnectionStateMachine`，且 Proxy Ready 事件必须匹配目标 Node 地址。当前删除流程优先复用这一判断，而不是 Site 列表中的云端在线图标。

**蓝牙显示已连接只能说明可以尝试，不保证 Reset 一定成功。** 因此必须保留有限等待和未确认成功的收尾处理；在线时刚好断连，也按“本地删除完成、需手动重置”处理。

## 4. UI 与文案

保留一次 Delete → Continue 的删除确认，取消 Reset 失败后的 FORCE DELETE／Cancel 弹窗。

第一次确认中补充：如果无法通过蓝牙完成重置，用户需要在重新添加前手动重置设备。这样确认一次即覆盖离线和中途断连的后果。

建议文案方向（实现时中英文同步本地化）：

- 确认补充，英文：`If the gateway cannot be reset over Bluetooth, you will need to reset it manually before adding it again.`
- 确认补充，中文：`如果无法通过蓝牙重置网关，重新添加前需要手动重置设备。`
- 本地已删除但 Reset 未确认，英文：`Gateway deleted. Reset the device manually before adding it again.`
- 对应中文：`网关已删除。重新添加前，请手动重置设备。`

完成说明使用删除后仍可见的 Site 页面提示，不增加一次强制删除确认。旧 `gateway_force_delete_note` 含有“强制删除”措辞，不直接作为新流程文案复用。服务器失败继续复用 `gateway_delete_server_failed`。

## 5. 修复范围保持聚焦

### Gateway 共用删除入口

WiFi 与 4G 在 `GatewayViewController` 共用上述流程。Site 主网络网关不再进入要求真实 Space 的 `DeviceProtocol.deleteNodes`；普通 Space 灯具、开关等设备的删除保护保持原有语义。

不以是否绑定 Associated Spaces 作为是否允许删除或是否发送 Reset 的条件。网关归属 Site 主网络，绑定 Spaces 不会改变这一归属。

### 本地收尾和并行导入

- 复用现有持久化待删除状态表达“服务器已成功、等待本地收尾”，必要时调整命名／内部阶段使语义清楚；无需离线云删除任务。
- Site 刷新在 Reset 尝试结束前不能抢先移除目标 Node，否则会导致命令无法发送；保护目标删除会话，收尾由单一入口完成。
- 服务器成功后的旧云快照、普通同步、授权重试不能把网关重新导入或重新注册。
- SDK 收到成功回执会自动移除 Node。本地收尾应幂等，使用提前捕获的 Site／主网络身份；没有成功回执的路径显式执行本地 Node 移除。
- 本地持久化失败／App 中断时保留可恢复状态。服务器已删除这一事实不能撤回，恢复的是本地收尾，不恢复普通网关上传。
- 删除会话只完成一次，迟到回执不得重复显示结果或删除后来重新添加的实例。

### 旧状态兼容

旧版本产生的 `serverDeletionPendingLocalReset` 记录在新版按“服务器已删除、待本地收尾”恢复。不能再弹旧 FORCE DELETE；不能按普通待上传 Gateway 重新注册。用户主动再次 Delete 仍使用统一联网入口，内部恢复不需要为了已确认的服务器成功重复删除请求。

## 6. 验证重点

| 场景 | 预期 |
| --- | --- |
| Owner／Editor 手机离线 | 删除不开始，本地与设备不变 |
| 权限拒绝、服务器失败 | 无 Reset，无主动本地删除 |
| 服务器成功、蓝牙就绪、Reset 回执成功 | 自动完成本地删除，无第二次确认，可重新添加 |
| 服务器成功、蓝牙未就绪 | 直接完成本地删除，提示手动重置 |
| 服务器成功、Reset 超时／中途断连 | 有限等待后完成本地删除，提示手动重置，无强制删除弹窗 |
| 服务器成功后手机断网 | 继续设备尝试及本地收尾 |
| 删除时 Site 并发刷新 | 不提前丢失 Reset 上下文，不重新导入／注册 |
| 本地持久化失败或 App 重启 | 可恢复收尾，不假报完成 |
| 未绑定、绑定一个／多个 Spaces | 同一删除规则，关联清理正确 |
| WiFi、4G 及全部共享品牌 target | 共用策略正确，相关本地化和 target 编译通过 |

按工程规则直接进行 generic iOS 构建。用户后续明确要求“不需要真机测试”，本次不进行真机或 Simulator 验证；实际 Reset、未配网广播、重新添加以及提示的真实显示效果不列入已验证项。
