# 删除全部设备后云端回读不一致

## 已确认的故障边界

本次 Use this phone's data 操作已走到上传阶段，本地导出成功且 repairs 为 0。当前故障发生在上传成功后的回读确认阶段。

| 阶段 | 实际日志 |
| --- | --- |
| 本地导出 | schema=1，groups=2，paths=2，spaceZones=2，repairs=0 |
| 上传 `/sitespace/sync/spaceprops` | `nodes: []`、`deviceCount: 0`，Path 地址全为 0，Space Zone 成员为空 |
| 上传响应 | HTTP 200，业务 code=200，message=success |
| 随后 `/sitespace/get/spaceprops` | `deviceCount: 0`、Path 为空，但 `nodes` 仍包含原来的 4 个设备 |
| App 判断 | `uploadReadbackUnconfirmed`，保留本地快照并将同步标记为失败 |

回读四个设备的主地址为 0031、0028、0040、0037。设备数量字段与设备列表不一致，仅凭 `deviceCount: 0` 不能确认删除成功。

因此同步提示没有消失，是回读校验确实发现不同配置。移除校验会把未确认的云端删除当作成功，其他手机或后续导入仍可能读回旧设备。前一轮 App 删除清理与恢复路径没有解决服务器侧设备列表残留；该问题不能以此前自动化测试或编译结果宣称已解决。

## 不能从现有日志断定的事项

- 未取得服务端实现，不能断言具体就是忽略空数组，也可能是只执行 upsert、不删除旧关联，或者 GET 使用不同数据源/旧缓存。
- 单次立即回读不能完全排除异步任务或读副本延迟；本例恢复前后都返回同样的 4 个设备，值得检查持续残留，但仍需版本与服务端追踪证据。
- 完整响应被截断，不能排除除 nodes 外还有其他字段不一致。节点列表不一致本身已经足够使校验失败。
- `Content-Encoding: gzip` 与明文 JSON 不匹配是已有传输异常，但当前请求已返回业务成功，且云端已有 deviceCount=0 和清空的 Path，不能把节点残留直接归因为该头字段。本次不同时改传输协议。

## App 已补充的处理

1. 将上传后回读未确认的错误从“Proximity lighting data is invalid and could not be exported.” 改为独立的云端同步未确认提示。真实导出失败继续使用原错误。
2. 普通 CloudSync 与解绑前上传使用同一个提示 Key，提供英文与简体中文。
3. 回读不一致日志记录提交/远端时间戳、提交/远端实际节点数、远端 deviceCount、远端多出/缺少的 UUID 数量及最多 8 个样例。不会输出密码、Mesh Key 或完整载荷。
4. 保留节点成员关系和配置一致性校验，不改写真实 Mesh UUID，不通过强制清空本地保护标记制造同步成功。

## 服务端修复检查顺序

1. 找到 `/sync/spaceprops` 的 `spaces[].nodes` 更新分支。区分字段未提供与显式空数组；对已接受的完整 Space 快照，空数组必须能表达该 Space 设备成员清空。检查非空判断导致跳过、空列表 SQL 分支及仅 upsert 无差集删除。
2. 追踪 `/get/spaceprops` 的 nodes 来源：Space JSON、设备表、成员关系表、Redis、缓存视图或异步投影。deviceCount、nodes、拓扑和版本必须来自一致快照。
3. 修改与删除必须限定同一 Site/Space 的成员关系。不同 Site 重复配网的设备即使 UUID 相同，也不能按全局 UUID 删除其他 Space 的记录；具体数据结构以服务端当前所有权约定为准。
4. 检查事务与版本：响应成功时实际提交了哪些表，空数组更新是否被旧时间戳忽略，是否有旧编辑端或后台任务再次写回设备。GET 日志记录同一请求的写入版本/读取版本和缓存命中来源。
5. 同时检查 `/sync/siteprops` 嵌套 Space 的同类分支，避免只修单 Space 上传。
6. 若服务端明确采用异步可见性，补充可追踪版本及有界确认方案；只有回读达到提交版本且配置一致才确认成功，不用盲目延迟或无限重试掩盖持久化错误。

## 服务端验收用例

- 4 个设备上传为 0 个，随后读取必须返回 `nodes: []`、`deviceCount: 0`，重启/缓存失效后仍一致。
- 4 个设备上传为 2 个，仅删除目标 Space 被移除的两个成员；另一个 Site 中相同 UUID 不受影响。
- 重复提交同一份空快照保持幂等，不恢复旧设备。
- 单 Space 上传与 Site 内嵌 Space 上传得到相同结果。
- 旧客户端或异步任务提交较旧快照时，不能覆盖已确认的新版本。
- 首次和再次回读的版本、数据库与缓存内容一致；服务端无法提交删除时返回可区分的失败。
