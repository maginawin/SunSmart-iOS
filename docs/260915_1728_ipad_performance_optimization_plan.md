# iPad 性能优化实施方案

## 1. 目标与范围

依据 [Release trace 分析](260915_1723_release_ipad_cpu_trace_analysis.md) 和 [28b918b 审查](260915_1717_review_28b918b.md)，按以下顺序实施：

**修复清理复用正确性 → 建立可比性能基线 → 消除同步状态重复文件读取 → 移出不可分片重计算并完善刷新合并 → 优化响应/导入/导出 → 优化列表。**

本文件是实施计划，本轮未修改生产代码、Scheme 或设备状态。

### 已知基线

| 问题 | 证据 | 计划处理 |
| --- | --- | --- |
| 旧后台并发扫描已改善 | subscriptions 33.904 秒降至本次 0.141 秒；旧 14 个后台同步检查链未见 | 保留去重、成员索引和过期回调保护 |
| 新刷新仍过重 | 主线程累计 16.252 秒；三段活跃窗口约 8～10.5 秒 | R2、R3 |
| 配置保护读取重复 | 刷新内部约 10.701 秒，约占 65.84% | R2 |
| 首次计划不可分片 | 6 ms 计时不能抢占整个拓扑；审查的复杂隔离数据使主队列延迟约 326 ms | R3 |
| 导入/导出/列表卡顿 | 9 次 >250 ms 卡顿，共 4.113 秒，最长 756 ms | R4、R5 |
| 运行时诊断干扰 | libRPAC 后台回溯 29.960 CPU 秒，占 52.71% | R1 |
| 清理复用缺少持久化 Space 一致性 | 调用者可能持有同时间戳旧对象，Mesh revision 不证明 Space 字段相同 | R0 |

旧 Debug 和新 Release 的构建/操作不同，以上用于定位，不作为精确优化收益。后续收益统一相对于 R1 的无诊断基线。

## 2. 总体设计

采用 **受控读取 → 不可变计算输入 → 单个后台计算任务 → 主线程校验并发布** 的流程。

- 主线程或对象现有所属队列负责捕获 live Mesh 中的必要设备状态；使用节点/Element/Model 游标分批提取，不一次序列化整个网络。
- 持久化 Space、保护文件及其他空间的 Site Zone 数据通过明确的存储读取边界准备，读取不改变活动网络、密钥或配置。
- 后台只接收值类型或保证独占的不可变数据，执行成员索引、拓扑、Site Zone 合并和纯校验。
- 主线程先做便宜的版本/身份校验，再进行剩余轻量节点判断或发布结果；不能继续在 getter 内隐式读磁盘、构造全空间计划。
- 最初不重写全部 Node 同步规则：优先迁移 trace 已确认的 I/O、成员、拓扑和 Site 计划；剩余轻判断保留原规则并分片。实测仍超预算的函数再逐项改为读取快照。

### 一致性版本

一个可复用结果至少绑定：

| 维度 | 内容 |
| --- | --- |
| 身份 | account、region、siteID、spaceID、meshUUID、networkID、当前网络实例代数 |
| 持久化配置 | App/Mesh 两个数据库的可验证 revision；不能只用秒级 lastUpdate |
| live 设备状态 | 会影响同步判断的观察值、待恢复编辑、成员状态的变更代数 |
| 保护状态 | 权限/恢复阶段、blocked、导入/引用清理/删除日志的变更代数和读取完整性 |
| Site Zone | Site 配置及所有参与空间的依赖版本、可读权限和历史成员目标 |

主线程比较的是已经准备好的 token，而非重新执行 SQL、Data(contentsOf:) 或路径探测。文件和数据库 token 的产生、校验由各自存储边界负责。两库和文件不是一个原子事务：读取前后核对版本，并拒绝写入进行中的混合快照。

## 3. 分阶段实施

### R0：先修复清理复用的正确性

**优先级：最高。独立小提交。**

涉及 `SpaceSyncCleanupCoordinator.swift`、`ConfigurationMeshReadSnapshot`、`SpaceSyncReadbackReuseTests.swift`。

1. 先补充旧 Space 对象与持久化 Space 为不同对象、同一时间戳但触发区域内容/加载状态不同的回归用例。
2. 在完整持久化快照契约完成前，取消“只凭 Mesh revision 和时间戳复用 original”的快速路径，恢复从重新加载 Space 执行回读校验。
3. 不回退整次 CPU 修复；仅收紧此复用条件。恢复二次回读可能短期增加清理耗时，这是正确性修复的明确代价。
4. R4 以完整持久化快照重新引入安全的复用：快照必须同时包含 Space 字段、Mesh、扩展数据、解码状态、读取 scope 和各版本，首次导出不得混用调用者旧 Space 字段。

**验证：** 同时间戳旧对象、损坏 triggerZones、初始化/恢复/删除写入、未知 revision、账号/权限改变、回读失败均不得错误调用 finishSyncReferenceCleanup；无变化且完整一致时才能恢复一次导出。

### R1：建立可比基线和测量点

R0 可先修；R1 是后续性能收益比较的基准。

1. 使用 Product → Profile 或让 Instruments 启动 Release App，排除 Run 注入的 Thread Performance Checker 等诊断成本。记录编译配置、优化级别、App UUID、SDK revision、设备/OS、数据规模及操作时间线。
2. 保留一份开启检查器的诊断录制；无检查器录制用于性能比较。关闭检查器不是业务修复。Apple 对这一区分有明确说明：[性能诊断与 profiling 建议](https://developer.apple.com/documentation/xcode/diagnosing-performance-issues-early?language=objc)。
3. 增加低开销区间测量：保护状态读取、live 状态提取、成员索引、拓扑/Site 计划、节点判断、发布、响应解析、Mesh 读取、导出、清理校验。
4. 记录每轮 cause、scope token、唯一节点数、计算次数、缓存命中、文件读取次数、取消/失效原因、主线程完整片段时间。测量点不得记录账号、密钥、完整业务 JSON。
5. 遵守项目日志规则，新增打印仅在 `#if DEBUG` 内。需要测 Release 时用 Instruments 和专用性能测试构建的区间测量开关；生产默认关闭，验证开关自身成本。
6. 不只统计循环：首次准备、preflight、版本检查和发布均计入主线程占用。

**数据集：** 原实际空间；500 节点/多 Model/多邻近照明组压力数据（参考审查 50 组×每节点 20 Model）；跨空间 Site Zone；零节点；无变化/有变更；缺失或损坏恢复文件。

**产物：** 每场景至少 5 轮冷刷新、10 轮暖刷新，区分进程重启与 OS 文件缓存状态；保存每操作 CPU 秒、墙钟时间、主线程片段分布、hangs、峰值内存。未完成 iPad 人工基线不阻塞有确定证据的修复，但不宣称已达到 iPad 指标。

### R2：配置保护检查改为批次快照

**预期收益最大，先实施。**

涉及 `SpaceConfigurationSafety.swift`、`NodeSyncReadContext.swift`、`Node+SyncData.swift`、恢复/导入/删除日志实际写入入口。

#### 读取

- 引入限定 scope 的保护状态读取结果，包含恢复 phase、阻止原因、各 pending 标志、权限、读取错误和版本；不能只缓存一个 Bool。
- 一轮有效刷新对每个依赖文件至多读取/解码一次；查询子函数复用结果，路径与 scope 哈希同时复用。
- 保留区分“文件确实不存在”“读取失败/不完整”。后者保持 unknown/blocked，不回落成可同步。
- `configurationAvailable(for:group:)` 仍检查对应节点/组及全网络损坏状态；网络级检查预计算一次，不能拿任意组的结果替代 contextGroup 语义。
- 命令发送、写入、导入/删除完成等决策继续使用正式的权限和恢复验证；UI 同步标记缓存不能成为执行授权。

#### 失效

逐项审计实际写入点，覆盖：saveState、block/unblock、authority change、begin/end import、引用清理建立/完成、deletion journal 修改、恢复/回执处理、active marker 清除、账号/区域/网络切换。

- 写操作开始即使旧快照失效并标记 mutating，完成后更新代数；失败或部分写入保持保守失效，不能继续使用旧的“允许”结果。
- 读快照采用同一存储协调边界或前后版本检查，避免并发写入期间读取混合文件。
- 只覆盖一个 Swift 文件内的 writer 不够：需要检查直接写相关路径、UserDefaults、数据库的其他入口。
- 未确认覆盖所有 writer 时，只做批次内缓存；跨批次复用暂不开启。恢复前台、重新加载账号及无法证明状态未变化时重新读盘；不能仅靠 TTL 或文件秒级 mtime 保证正确性。

#### 节点内部重复检查

`getNeedSync()` 会再次以显式 group 调用 `getNeedSyncGroup(group:)`。建立包含 effective group/override/成员状态的结果键，只有语义等价时才共享；恢复组、待加入组和 nil group 不默认等价。

**验收：** 节点循环和 isCurrent 在主线程不读取保护文件；文件读取量按依赖文件/空间数增长；任意阶段的保护变化可阻止旧结果发布。用真实临时文件验证，禁止继续只以恒定 true 的保护替身衡量性能。

### R3：重计算离开主线程，完善刷新生命周期

涉及 `NodeSyncStatusRefresh.swift`、`NodeSyncReadContext.swift`、`GroupProximityLightingData.swift`、`SiteTriggerZoneTopologyReader.swift` 和三个 UI/预热入口。

#### 快照与计算边界

1. 以节点、Element、Model 为游标渐进提取需要的标量、订阅/发布信息和配置字段。先审计 SDK getter：不允许把“复制快照”实现为主线程完整 Mesh 导出/JSON 深拷贝。
2. 对 DB-only 数据使用明确 scope 的只读连接/适配器，核对事务和 SDK 访问方式；不把全局单例或可变 Mesh/Node/Group 引用传到后台。
3. 后台构建一次节点→组、组→节点、组地址字符串、订阅集合、日程目标、基础空间拓扑及 Site Zone 目标。普通/虚拟/特殊地址、主 Element All Nodes、exitFailure、additionalGroupMembers 和恢复组保持原语义。
4. Site Zone 跨空间读取保持权限/密钥/版本保护；失败空间为 unavailable，不能当空集合，也不改变活动网络。
5. 若需要 SDK 提供更轻的只读订阅接口，先检查本地 `one-dev` 开发路径，按项目规则开发并验证所有品牌；首选 App 内投影，不预先扩大 SDK 改动。

#### 任务调度

- 同一 scope/version 只有一个计算任务，Cell、设备页与预热共享。
- owner 更新替换旧请求；显式保存处理进度，不在每个片段从节点列表开头重扫缓存结果。
- 可见节点/组优先出结果，预热处理剩余集合；安排公平进度，避免频繁 UI 请求让预热永久饥饿。
- 取消、切换空间、版本变化后，在提取/计算阶段设置协作取消点；发布前核对 owner、身份和所有版本。
- 连续变更时只保留最新待处理请求，旧任务不可无上限并行或不断紧密重启。等待变更稳定的调度不得显示旧版本为“已同步”。
- writer 覆盖验证通过后，只保留当前空间最新有效结果及依赖版本；同一完整版本的重复页面刷新复用完成结果。切换空间、内存压力或失效时释放，不做无界多版本缓存。

#### 主线程预算

软预算覆盖整片提取、判断、校验、发布；一次调用超过预算必须拆解或迁移。单纯降低循环预算、增加 global queue 或把整个现有 Node 检查塞进 Task.detached 都不满足要求。

**验收：** 复杂首节点场景不再阻塞后续主队列回调约 326 ms；同一版本 14 个请求仍只有一轮全空间计算；取消、持续变更和跨空间时旧结果零发布；暖刷新不重复建计划。

### R4：响应、导入、导出与清理分阶段处理

分为可独立验证的小提交，不一次迁移整个异步链路。

#### R4a：避免主线程再次遍历大响应

- `NetworkRequest` 后台完成一次解码与必要字段提取；避免为 code/isSuccess 等字段重复包装整个 JSON。
- `SiteViewController.performSiteLoad` 接收已提取 data 或明确 DTO，不在主线程执行递归 `JSON(response)`。
- 保持业务错误码、缺失/空值、字段类型容错、时区协调和权限处理一致。

**验收：** 原约 495 ms 的主线程 SwiftyJSON 包装链消失；后台解码次数和内存副本数量可测。

#### R4b：Mesh 载入和空间导入

- 区分只读载入/解码/密钥衍生、纯计算、事务写入、应用活动网络四阶段。
- 优先复用 scope 与完整 revision 一致的已载入网络；不用逐节点重复重建公共 NetworkKey 衍生数据。
- 只读和纯计算迁入存储/计算所属队列；事务、sequence number、授权、回滚/恢复标志和 live 网络更新继续按既有安全边界执行。
- 不将全部导入直接从 MainActor.run 改为后台；逐一消除函数对当前 manager 和共享对象的隐式依赖。

#### R4c：完整持久化导出及清理

- 构建同时包含持久化 Space、Mesh、GroupInfo、场景/日程/开关、Space/Site Zone 依赖及错误状态的导出输入。
- 读盘、拓扑快照、JSON 编码和 normalize 等纯计算后台执行；提交前/清理完成前检查版本和恢复上下文。
- 修复 R0 所需的完整一致性后，重新启用无变化清理的一次导出；复用范围限同一操作及完整版本。
- `extensionChanges` 将“找出变更”与“执行写入”分离：后台生成值类型修复计划，原所属队列验证后提交。不把捕获 live SDK 对象的写闭包跨线程传递。
- 上传仍绑定确定的提交快照和回执规则；未持久化的 live 编辑不能混入被称为持久化的导出。

**验收：** 原约 508/532 ms 导出和 756 ms 清理段不再由主线程执行重计算；R0 的陈旧/损坏数据用例仍无法错误完成清理；导出字段和已有兼容语义保持一致。

### R5：消除列表中的同步全网扫描

涉及 `GroupsViewCell.swift`、`GroupsViewController`、`DevicesViewCell`、`DeviceLightsViewController`、`SpaceViewController`。

- 列表展示模型预先提供组开关状态、待同步状态、名称/图标；Cell didSet 不直接通过 Group.isOn→Group.nodes 扫描网络。
- 开关观察值与配置同步结果分别失效，BLE on/off 更新仍及时展示；身份和复用 token 校验保留。
- 合并进入空间/拓扑协调后的重复 reload，只刷新变化项，保持分页、编辑、空态、过滤和选中状态。
- 依据 trace 检查 Device Cell 初始化、重复约束创建和属性赋值；不顺手重做界面布局。

**验收：** 组页面不再出现约 99 ms 成员扫描；快速滚动、切页、编辑和 Cell 复用无错图标/旧状态；真机实际检查布局与交互。

## 4. 验收指标

以下是规划目标，不是已测得的保证；以 R1 固定场景与硬件验证，未达标必须报告剩余瓶颈，不能仅凭降低 CPU 峰值宣称完成。

| 维度 | 首轮目标 |
| --- | --- |
| 数据正确性 | 陈旧、混合、损坏快照零错误放行；保护失效后零旧结果发布 |
| 主线程 I/O | 同步标记的节点循环及 isCurrent：0 次保护文件读盘 |
| 去重 | 同一完整版本的重叠请求：1 个计算任务、1 次基础拓扑；后续未变化刷新不重算 |
| 主线程片段 | 提取/轻判断/发布的 P95 ≤8 ms，最大目标 ≤16.7 ms；首次准备同样计入，超限必须拆分 |
| 可见结果 | 500 节点参考场景首批可见同步标记目标 ≤300 ms；完整冷刷新目标 ≤1 秒 |
| 总计算量 | 同一操作的同步状态 CPU 秒较无诊断基线减少至少 80% |
| 卡顿 | 固定复现流程中，由本次覆盖链路造成的 >250 ms hang 为 0；同时观察短片段和滚动指标 |
| 内存 | 活跃任务/快照数量有界；重复切页后无阶梯式增长，记录峰值而非用耗内存换瞬时 CPU |
| 蓝牙 | 刷新期间服务发现/通知回调无新增主队列阻塞；超时是否改善单独用对应日志验证 |

对于跨空间 Site Zone 或超过参考规模的数据，分别建立规模基线；不以降低安全验证强度满足耗时目标。瞬时多核 CPU 本身不是唯一失败指标，必须同时看总 CPU 秒、完成时间和主线程响应。

## 5. 测试与交付

### 必须补齐的真实边界测试

- 输入旧 Space 对象与 SQLite 持久化对象分离；同时间戳不同 Zone、解码失败标志及字段变化。
- 真实临时恢复目录：文件不存在、无权限/读取失败、损坏 JSON、读期间原子替换、写失败、pending 状态迁移、前台恢复。
- 真实 SDK 字符串订阅与多 Model 数据；普通/虚拟/特殊组、默认 All Nodes、地址碰撞和设备替换。
- 完整保护、Profile、日程、Scene、开关、紧急/消防关联判断；不能继续用“永远允许”的保护替身做性能结论。
- Site Zone 跨空间变化、账号/权限撤销、待恢复删除、连续 BLE 状态更新，以及计算期间网络切换。
- 新旧纯规则输出对照，不在真实主线程额外执行旧重算法。测量及验证不得写云端或发送真实控制命令。

### 现有回归

按阶段运行相关 `check_node_sync_status_refresh.py`、`check_space_sync_readback_reuse.py`、清理/恢复回执、邻近照明、Site Zone、日程、同步执行器及 Site 时区用例；改到共享边界时再扩展，不对每个小提交重复全量测试。

### 构建与真机

- 使用直接 xcodebuild、iphoneos、generic/platform=iOS；不使用 Simulator。新增文件同步五个品牌 target；共享代码/SDK 变化后检查所有受影响 target。
- 自动化与初步性能验证使用 **MtestiPhone15**；iPad LLH 按项目规则由人工操作和录制。
- UI 变化须真机运行检查；不以编译、单个截图或隔离用例通过代替最终体验验收。未完成原设备复测时清楚列出限制。
