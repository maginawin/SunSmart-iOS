## 结论与范围

保留普通云端导入、导出和同步的拓扑安全判断。修复明确删除操作的持久化清理，并为历史残留引用提供需要用户审阅的恢复入口。没有修改 SDK、服务器接口或加入认证信息。

## 已实现

### 明确删除

- 删除前捕获目标 Site、Space、Mesh、子网、Node UUID 和完整相关 element 地址；先保存 checkpoint 和删除意图，成功后才允许 Reset 或强制移除。
- 单灯、Dongle、批量灯和共享设备删除入口均使用同一删除上下文。失败取消保留仍存在的设备；已移除的设备不会因超时回调而丢失清理记录。
- 针对本次确认已删除的地址，清理 Group Path、Group Zone、Space Trigger Zone 和关联扩展记录。保留 Group、Profile、空槽及未删除设备的配置。
- 批量 Reset 先移除多个 Node、再逐个回调时，联合处理已确认缺失的设备，避免每次只清一个地址而被剩余残留引用拦截。
- 清理提交后重新读取数据库并检查拓扑，成功才标记完成。失败保留记录，重新进入 Space 时重试；不会显示虚假的 Done。
- 清理始终按原 Site/Space 身份执行。当前手机切换到另一 Site，即使 UUID、地址或 Network ID 相同，也不会使用另一个 Site 的设备数据。
- 清理完成通知更新当前页面持有的 Space 对象，避免旧 Trigger Zone 内容回写。

### 历史数据恢复

- 普通 Reload 仍不自动接受需要删除引用的云端拓扑。诊断日志新增具体 repair 类型、地址和本地/远端节点数量。
- 恢复菜单保留取消操作，提供 Reload cloud data 和本地恢复入口。
- 对可确定的悬空引用/重复引用，展示本地设备数量、云端设备数量和修复数量；保存双数据库 checkpoint 及修复前本地、云端 JSON，再由用户确认本地修复。
- 审阅后再次检查本地快照、时间戳、权限和云端版本；不允许绕过未完成导入、无法读取的 Profile、未知 schema 或其他不可确定的拓扑错误。
- 修复后的本地配置等待上传与回读确认，在此期间阻止旧云端快照复活已删除设备。
- 新增文案同步提供英文与简体中文。

### 上传确认与终止生命周期

- 删除回执只在清理已完成、且本次已验证上传的时间戳覆盖清理版本时结束；较早上传回调和未完成清理不能结束回执。
- 设备重新配网使用相同 UUID，或其他设备复用旧地址，属于后续有效配置，不再永久阻挡旧回执结束。
- 首次 Site 创建同样执行 Space 逻辑配置回读。资源分配变更不参与逻辑配置比较。创建请求已接受的 Site 会保存创建状态，后续回读失败不会再次错误选择 siteAdd。
- 解绑前的直接上传使用共享回读验证，并按实际提交时间戳确认，避免用回调时的最新 lastUpdate 确认未提交修改。
- 本地 Space 删除及 Site 下全部 Space 删除成功后，将对应恢复目录移入归档并清除活跃标记，保留诊断文件；重新导入时不继承已结束生命周期的回执。
- 保留本地配置时，仍先按返回 Space 身份应用服务器权限、密码事件、成员和网关状态。访客、需要密码验证或被禁用编辑权限时不能提交配置；恢复前的云端检查也更新权限。
