# Sync device(s) 设备行箭头与沙漏交替闪烁：定位及方案

本轮按用户询问先完成定位和建议方案，未修改运行代码，未运行构建或真机测试。

## 定位

1. `SyncDeviceStepModel.state` 在前一个任务已完成、下一个任务尚未开始时，因为没有 `.inSettings` 任务，会返回 `.wait`。
2. `SyncDevicesModel.state` 从各步骤状态聚合。当所有步骤均为 `.none`／`.wait` 时，设备也返回 `.wait`；开始下个任务后恢复 `.inSettings`。这种情况尤其容易出现在第一个步骤连续执行任务期间。
3. `SyncDeviceViewCell` 对带步骤的设备行，在 `.wait` 时隐藏箭头，并将 `device_add_waiting` 图标放到右边距 16 的位置；在 `.inSettings` 时隐藏状态图标并显示箭头。箭头也位于右边距 16，因此两个图标在同一位置交替出现。
4. 上一轮 `refreshVisibleSyncCells()` 对步骤行使用局部更新，但对设备行仍执行 `cell.model = model`。每次进度变化都会重跑完整绑定、动画移除／添加、图片与约束配置。取消 reloadData 本身不足以消除状态映射造成的切换。
5. 分组行也直接读取原始聚合状态，需要同步核查是否出现等待图标反复出现；Proxy 行共享 Group Cell，必须保持模型身份校验。

## 推荐方案

采用“本轮稳定的显示状态 + 控件差量更新”，聚焦这次闪烁，不扩展为整个同步控制器重构。

### 设备行显示规则

| 阶段 | 带步骤的设备行右侧 |
| --- | --- |
| 本轮尚未执行到该设备 | 保留等待沙漏 |
| 已开始执行，设备尚未结束 | 保留箭头；方向根据真实 `isShow` 展开状态确定 |
| 两个任务的短暂交接间隙 | 保持执行中的显示，不退回沙漏 |
| 设备成功／失败 | 按既有规则显示结果图标、箭头和允许的重试／选择控件 |

箭头只随实际展开／收起改变方向；本次不新增执行中的手动展开交互。成功、失败、停止和依赖导致的结束继续遵循现有业务规则，不能为了稳定图标掩盖真实结束。

### 实施边界

- 在当前同步轮次的展示上下文记录设备／分组是否已经开始。开始记录由实际任务开始事件驱动，并在新轮次及重试时正确重置；不能单纯根据历史成功任务推断“本轮已开始”。
- 显示状态记录不放在可复用 Cell 内，避免离屏回来、自动展开或 Cell 复用后重新出现沙漏。旧轮次更新不得污染新轮次记录。
- 保留任务模型的原始 `.state` 给调度、依赖判断、成功判定等业务逻辑使用，展示规则只用于 UI。
- `SyncDeviceViewCell` 拆分首次绑定与状态更新，比较显示快照；进度改变但设备行显示状态未改变时，不重设图片、隐藏属性、约束，也不重启动画。
- 显示快照包括模型身份、显示状态、展开状态、完成标志、选择及失败信息，避免仅比较 state 后漏掉箭头方向、失败重试或选择变化。
- Group 行同步检查等待状态回退；保留既有 Group 箭头展示和点击规则。Proxy 行保留专用展示分支及复用保护。
- 带步骤设备行和无步骤设备行分别保留原有布局：无步骤设备不因此增加箭头。

## 验证及验收

1. 连续任务、首个任务失败后继续、步骤切换：已开始设备不在箭头与沙漏间切换；状态未变时不发生重复控件更新。
2. 设备／分组自动切换：未开始设备仍显示等待，当前设备保持运行显示，已完成设备及时显示结果。
3. 重试保留成功任务、停止、新轮次开始及旧回调：显示状态能正确重置，不能把历史进度当作本轮已执行。
4. 滚动离屏返回、复用、展开／收起、Group／Proxy 行：显示身份与真实模型一致。
5. 保持左侧步骤进度 Label 不闪的既有回归通过，并直接执行 generic iPhoneOS 构建。
6. 按项目 AGENTS.md，在用户选定的实际设备上验证连续同步和完整约束、横竖屏布局及右侧图标视觉表现。状态测试和编译不能代替该验收。
