# Site 顶部网关列表最小宽度与横向滚动优化方案

## 目标与结论

保留现有按数量均分、最多按四项计算的宽度算法，并为每项增加 112 pt 最小宽度；超出空间时通过横向滚动浏览全部有权限查看的网关。沿用方案中的左侧固定 Overview、中间横向网关列表、右侧固定菜单布局；“固定”指两侧的位置，Overview 的宽度与网关项一起按公式计算。

按用户补充，取消上一版 Overview 88 pt、网关项始终 112 pt 的设定。令 N 为当前展示权限内的网关总数，W 为表头宽度扣除右侧菜单实际预留宽度后的可用宽度；N ≥ 1 时，Overview 与每个网关项统一使用 `max(W / min(N + 1, 4), 112 pt)`。N = 0 沿用现有空状态，不套用公式。

| 网关数量 | 均分基准（含 Overview） | 最终每项宽度 |
| --- | --- | --- |
| 1 个 | 2 项 | `max(W / 2, 112 pt)` |
| 2 个 | 3 项 | `max(W / 3, 112 pt)` |
| ≥ 3 个 | 4 项 | `max(W / 4, 112 pt)` |

菜单区域沿用现有 `SCRXFrom(40)` 预留宽度，并使按钮区域与之保持一致；保留现有列表高度。112 pt 是整个可点击项的宽度下限，包含文字、状态点、同步失败图标和留白，不再经屏幕比例缩放。名称保留单行、中间省略的现有行为。图标占位可能使文字区域变小，但整个项不低于 112 pt。

## 当前代码证据

- `SunSmart/Main/Site/View/GatewayListView.swift`：`updateLayout()` 按可用宽度除以可见项数量平均分配；`maxVisibleItemCount = 4` 包含 Overview；`calculateVisibleItemIndexes()` 在超额时保留前三项与当前选中项；`scrollView.isScrollEnabled = false`。
- `SunSmart/Main/Site/Controller/SiteViewController.swift`：`makeGatewayListItems()` 在网关列表头插入 Overview；菜单可选择全部 `showGatewayModels` 中的网关。`setupData()` 通过网关 MAC 保持选择并刷新两个 collection view；表头配置目前先调用 `updateItems()`，再设置 `selectedIndex`。
- `SiteGatewayHeaderView` 同时用于 All Spaces 与 Favourites。外层 `PopGestureScrollView` 支持横向分页，因此新增内层横向滚动需要明确手势归属。

## 确定的展示与交互

| 项目 | 方案 |
| --- | --- |
| Overview | 固定在最左侧，宽度使用同一公式，始终可以点击返回总览 |
| 网关项 | 按原均分规则计算并取 112 pt 下限；超过三个网关后不再因数量增加而缩窄 |
| 网关顺序 | 沿用现有数据顺序，移除最多三个网关和选中项替换末项的限制 |
| 横向滚动 | 仅中间网关区域滚动；项宽只由公式决定，不按剩余空间二次拉伸或压缩 |
| 菜单 | 固定最右侧，沿用现有预留宽度，保留全部网关选择和添加入口 |
| 文字与状态 | 复用现有字号、颜色、选中下划线、状态点、待同步颜色与失败图标；长名称中间省略 |
| 溢出提示 | 允许下一项部分露出，启用系统横向滚动条；不新增提示文案或资源 |
| 菜单选择 | 更新业务选择后，最小距离滚动，使选中项完整可见；不移动该网关的数据顺序 |
| 选择 Overview | 恢复总览筛选，网关列表保留浏览位置，便于继续切换 |
| 零网关 | 沿用现有权限判断、添加网关按钮或隐藏表头行为 |

“Overview + 3 个网关”是 ≥ 3 个网关时的均分基准，不保证触发最小宽度后仍能在一屏完整展示四项，也不限制可滚动访问的网关总数。数量从 1 增至 3 时允许按原规则变窄，但不得小于 112 pt；数量超过 3 时项宽不再变化。屏幕或窗口宽度改变时按新的 W 重新计算。

令最终项宽为 L，中间网关视口宽度为 `W - L`，网关内容宽度为 `N × L`。例如在 375 pt 宽 iPhone 上，左右各 16 pt 边距、菜单预留 40 pt 时，W = 303 pt：1 个网关时每项 151.5 pt，正好填满；2 个网关时每项 112 pt，开始横向滚动；≥ 3 个网关时每项仍为 112 pt。Overview 占 112 pt，中间视口为 191 pt，显示一个完整网关及下一项的一部分。

较宽视口示例：W = 480 pt 时，1、2、≥ 3 个网关的项宽分别为 240、160、120 pt；三个网关可与 Overview 一起完整展示，第四个起通过横向滚动访问。实施时复核现有字体适配下的英文 Overview、中文总览与图标组合。

## 刷新、选择与滚动状态

1. 保持现有委托语义：Overview 对应索引 0，网关对应原数据索引 1…N。拆分展示区域不改变业务回调映射。
2. 表头完整配置时，将数据和最终选择一起提交给网关列表，再布局与定位，避免先按旧索引滚动再按新索引滚动。状态更新入口同步核对。
3. 相同网关 ID 顺序下，仅更新名称、在线状态、颜色和图标，尽量复用 item view；普通状态刷新不自动拉回选中项，不打断用户浏览。
4. 仅首次展示、业务选择改变或选中项因尺寸变化被裁切时，执行确保选中项可见。用户主动横向浏览时，允许已选网关离开视口。
5. All Spaces、Favourites 各自保存临时滚动位置，随当前页面生命周期存在，不写数据库。表头复用时恢复对应分页状态，避免两个分页互相覆盖。可用首个可见网关 ID 与项内偏移记录位置；网关增删后按 ID 恢复，并限制 offset 在合法范围内。
6. 所选网关删除或权限变化导致不可见时，沿用 `setupData()` 回退 Overview；浏览锚点不存在时回退到最接近的合法偏移，空列表归零。
7. 点击与菜单选择定位可使用短动画；数据刷新与表头恢复不使用滚动动画。布局过程中不反复触发定位。

## 嵌套手势

预期：在可滚动的网关区域左右拖动只浏览网关，即使到达两端，也不切换 All Spaces / Favourites；从其他页面区域左右拖动仍保留分页行为，垂直拖动仍可滚动空间列表。

实施先核对 UIKit 的实际手势竞争，再以 Site 页面范围内的内外层 pan 识别关系保证此行为。只对该网关区域作定向处理，不全局修改 `PopGestureScrollView`，不关闭整个页面的分页能力，也不在每次刷新或复用时重复安装手势关系。系统边缘返回手势保留现有行为。

## 最小实施范围

1. `GatewayListView.swift`：复用 `GatewayItemView`，分离位置固定的 Overview 与网关滚动区域；移除四项截取逻辑，但保留宽度公式分母上限为四；统一计算项宽与真实内容宽度；分隔线随所属项布局，菜单分界固定；补齐原子配置、选中项定位与临时滚动状态接口。
2. `SiteViewController.swift`：接入最终选中项配置、两个分页各自的滚动状态和必要的局部手势协调。沿用现有权限过滤、MAC 选择、菜单、空间筛选与刷新机制。
3. `SiteGatewayHeaderView.swift`：仅在需要转发配置或复用状态时作小范围调整，现有状态栏和时区提醒布局不变。

继续使用现有 UIScrollView 与 item view，不新增依赖或另建网关集合视图框架。这意味着包含 Overview 的视图数量由最多四项变为 N + 1 项；使用较大列表样本检查刷新成本。如果出现实测性能问题，再根据证据决定是否需要复用型列表，不提前重构。

共享视图影响 SunSmart、Archipelago、SLG Sync Plus、SylSmart、Lumineux。当前方案不修改 SDK、依赖、资源归属或用户可见文案，无新增国际化 Key。
