# 空 Group 地址比较兼容最小修复

## 问题与结果

现场唯一差异为 memberships[0].groupAddress：本地待确认提交缺少该字段，云端返回精确空字符串。旧比较据此反复产生 uploadReadbackConflict，并阻止较新本地修改上传。

本轮基于 `b970d0ca` 实施用户确认的最小修复：这两种无地址表示在逻辑配置比较时统一为缺省。不会因此忽略真实地址、设备身份、groupState 或拓扑差异。

## 实现范围

- `SpaceConfigurationIntegrityPolicy.swift`：在共享配置序列化入口移除 memberships 中精确空字符串的 groupAddress；提供已有配置 Data 的同类规范化与等价比较。
- 已有配置采用 memberships 结构，直接保留该结构与其他字段，不当作原始 nodes payload 重新提取，避免丢失设备成员。
- `SpaceConfigurationSafety.swift`：持久提交确认、prepared 提交的旧基线检查、权限恢复的基线及待提交比较，使用相同等价规则。
- 脱敏差异日志使用与实际比较一致的规范化配置。
- 未改写网络载荷、数据库设备内容或恢复记录格式，也不需要清空现有 pending。原提交 ID、阶段、版本、生命周期和权限约束保持有效。
- null、空白字符串、0000、非法地址、数值 0 和真实地址仍与缺省不同。本轮没有放宽其他空字段规则。

## 当前失败 Space 的预期恢复

重新编译运行后，原 accepted 提交可以使用已有恢复入口再次回读。若仍只有日志中已确认的空地址表示差异，应确认版本 1788779974，并结束对应提交与回执。

本地较新版本 1788781814 不会被当作已经上传。现有同步管理器在旧提交确认后继续检查 needUploadCloud，导出并上传最新配置；最新版本也通过确认后才完成同步。

真实远端差异、网络错误、权限问题或持久化失败仍会走原保护流程，不通过强制清除标记制造成功。
