## 1. 测试范围与使用说明

本次检查国家或地区、城市、时区、纬度、经度，以及时区对应的夏令时信息。

这里的夏令时是 **Daylight Saving Time**，指部分地区在一年中的某些时间调整当地时间。代码中的 **Daylight Harvesting** 是根据环境亮度调节灯光，属于另一项功能，不在本文范围内。用户提出的 “time zone with daylight harvesting”，本文按这三个页面实际提供的“时区与夏令时”功能编写。

| 页面 | 从哪里进入 | 本次检查内容 |
| --- | --- | --- |
| Create Site（创建场所） | Site 列表 → 添加 Site | 国家或地区、城市、时区、当地时间、夏令时、经纬度、使用当前位置、创建后保留填写内容 |
| Edit Site（编辑场所） | Site 列表中该 Site 的菜单 → 编辑；或进入该 Site → 菜单 → 编辑 | 与创建页共用的填写功能，以及取消、保存、断网、重新进入后的内容 |
| Gateway（网关详情） | 进入 Site → 打开该 Site 的网关入口 → 选择网关 | Site 时区、夏令时说明、网关时间、当地时间、更新时间；分别检查 Wi-Fi 网关和 4G 网关 |

国家、城市和经纬度在创建、编辑页填写，网关详情没有这些填写项。网关详情的时区与夏令时仅供查看，修改时区需进入 Edit Site。网关通过手机蓝牙连接并准备好后，才显示本次检查的时间区域；网关联网不等于手机已连接它。

执行约定：

- 第 4～8 节的共同功能，**Create Site 和 Edit Site 各执行一次**。第 9 节专门检查编辑后的保存结果。
- 除用例另有说明，手机联网，使用 Site 所有者账号，填写有效且不重复的 Site 名称；编辑时选用没有等待上传内容的测试 Site。
- “保存”在创建页指点 `CREATE`，在编辑页指点 `DONE`。编辑后如出现时区确认提示，按用例要求确认或取消。
- “重开 App”指完全关闭测试 App 后重新打开；不要求删除 App，也不要清除日常使用的数据。
- 用例中的英国、伦敦、新加坡、中国、深圳等是便于操作的例子，以测试时实际提供的列表为准。列表中没有某个例子时，换用满足相同条件的项目，并记录名称。
- 每项结果填写“通过”“不通过”或“未执行”。缺少设备或特殊资料时写明原因，不记为通过。

## 2. 开始前准备

| 准备项 | 要准备什么 |
| --- | --- |
| 测试手机 | 安装本分支对应的测试 App，记录 App 版本、手机型号、系统版本和测试日期 |
| 账号 | 一个 Site 所有者账号；一个只能使用别人分享的 Space、不能编辑整个 Site 的账号 |
| 测试 Site | 一个无网关的 Site；一个有网关的 Site；一个以前版本创建、部分位置内容未填写的 Site |
| 国家和城市 | 两个不同国家或地区；同一国家下两个不同城市；如列表存在同名城市，也准备一组 |
| 时区 | `Asia/Singapore`、`Europe/London`，以及带半小时或四十五分钟的时区，例如 `Asia/Kolkata`、`Asia/Kathmandu` |
| 手机时区 | 至少有一次测试让手机时区与 Site 时区不同，例如手机用新加坡，Site 用伦敦 |
| 网关 | Wi-Fi、4G 网关各一台；可正常连接；有条件时再准备同一 Site 下两台网关和另一个 Site 的网关 |
| 网络情况 | 正常联网、手机断网但蓝牙开启、网关断网但仍可由手机蓝牙连接 |
| 经纬度例子 | 普通值 `1.2801`、`103.8501`；负数 `-33.8688`、`-70.6693`；零；范围边缘值；不合法内容 |
| 特殊测试资料 | 请开发人员提供：没有城市的国家、同名城市、无法识别的旧城市、时间资料读取失败、夏令时切换前后、保存失败等可重复检查的测试条件 |

夏令时的当前状态和下次切换日期会随测试日期改变，不能固定要求伦敦一定显示“已启用”或“未启用”。开始前请提供测试用时区的正确当前时间、当前时差、下次切换时间和切换后的时差，作为比对依据。需要观察切换过程的用例，应使用事先准备好的测试时间资料；只修改手机日期不能代替完整的切换测试。

## 3. 当前代码中需要先说明的表现

这些是编写用例时确认的现有行为，不代表另行提出的新需求。

1. 国家、城市、时区旁边虽然有星号，但当前保存检查没有要求它们必须填写。经纬度可以同时留空，也可以只填其中一项。
2. 选择一个不同的城市，会重新填写时区、纬度和经度，包含覆盖此前手工修改的值。再次选择同一个城市，则保留手工修改。
3. 在同一次填写过程中，更换国家会清空城市；由城市刚刚带出的经纬度会清空，时区回到打开页面时的值。手工改过的经纬度、手工选过的时区，以及“使用当前位置”得到的经纬度会保留。重新进入编辑页时，已经保存的值也会保留，直到选择新的城市或手动修改。
4. “使用当前位置”只填写纬度和经度，不自动改变国家、城市、时区、街道地址或邮编。
5. 夏令时区域没有开启或关闭的开关。创建、编辑页可以展开说明；网关页只有简要信息，不能展开说明。
6. 夏令时区域只有在已取得下次切换时间和切换后时差时才显示。因此，“没显示夏令时区域”不能单独证明该地区不使用夏令时，也可能是时间资料尚未取得。
7. 编辑内容先保存在手机里，再尝试上传。上传失败不等于刚才填写的内容被撤销；网关是否已更新时间，还要另行检查。

执行时另行记录以下文案疑点，不把它们误写成操作步骤：

| 位置 | 当前需要核对的地方 |
| --- | --- |
| 国家、城市、时区标题 | 星号容易让人以为必须填写，但当前代码允许未填写时保存 |
| 断网修改时区的提示 | 文案说时区更新需要联网，但点 `Got it` 后，当前代码会把修改保存在手机里，等待之后上传 |
| 夏令时展开说明 | 英文说明提到再次切换夏令时设置，但当前页面没有这个开关；不要要求测试人员寻找不存在的开关 |
| 夏令时英文状态 | 当前“未启用”的英文显示为 `Unactive`，请记录文案是否需要调整 |

## 4. 国家或地区、城市的选择与搜索

- [ ] **L01 打开国家列表**

  **操作步骤：** 进入页面；点 `Country / Region`；等列表显示；选择一个国家

  **应看到的结果：** 国家名称填入页面，列表收起；没有自动替用户选择城市

- [ ] **L02 搜索国家**

  **操作步骤：** 分别用列表中某个国家的英文名片段、大小写不同的英文名、两字母简称搜索；中文名称已提供时，再用中文搜索

  **应看到的结果：** 能找到对应国家；例如新加坡可用 `Singapore`、`singapore`、`SG` 搜索；中英文可显示不同名称，但选择的是同一个国家

- [ ] **L03 国家搜索无结果**

  **操作步骤：** 输入明显不存在的文字；再清除搜索文字

  **应看到的结果：** 先显示没有找到国家或地区；清除后恢复列表；原先选好的国家没有被删除

- [ ] **L04 未选择国家先点城市**

  **操作步骤：** 在国家为空的页面点 `City`

  **应看到的结果：** 提示先选择国家或地区；不能从其他国家的城市中随便选择

- [ ] **L05 搜索并选择城市**

  **操作步骤：** 选择国家；打开城市列表；输入城市名的一部分；点一个结果

  **应看到的结果：** 只出现该国家的城市；选择后显示城市名称，并带出该城市的时区和经纬度

- [ ] **L06 城市搜索无结果**

  **操作步骤：** 已选城市后，重新打开城市搜索；输入不存在的名称；点页面其他位置

  **应看到的结果：** 搜索时提示没有找到城市；收起后仍显示原城市，时区和经纬度不变

- [ ] **L07 清除搜索不是删除选择**

  **操作步骤：** 先选好国家、城市；分别打开搜索，输入文字，再点输入框的清除按钮；不选择新项目，点其他位置收起

  **应看到的结果：** 清除的只是搜索文字；原来确认的国家和城市仍保留，不自动变为空

- [ ] **L08 国家和城市之间切换**

  **操作步骤：** 打开国家搜索并输入文字；直接点城市；再直接点国家

  **应看到的结果：** 同一时间只展开一个列表；第二个列表可以正常使用，不会刚打开就消失；未确认的搜索文字不替换原选择

- [ ] **L09 快速改变搜索内容**

  **操作步骤：** 在城市搜索中快速输入、删除并换成另一个名字；等待结果出现；选择最后一次搜索中的城市

  **应看到的结果：** 最后显示的是最新搜索结果；较早搜索的结果不会随后覆盖页面；保存后仍是最后选中的城市

- [ ] **L10 同名城市**

  **操作步骤：** 使用准备好的同名城市列表；分别选中两个同名项目，记录带出的经纬度

  **应看到的结果：** 列表通过括号中的经纬度等内容区分同名城市；选择不同项目时，填写的是各自的位置和时区

- [ ] **L11 从未取得列表时断网**

  **操作步骤：** 使用未取得过国家、城市列表的测试 App；断网打开国家；恢复网络后再次点国家输入框；对未打开过的国家的城市列表重复检查

  **应看到的结果：** 断网时结束等待并提示读取失败；再次点击可以重试；成功后可选择，不一直显示正在读取

- [ ] **L12 已取得列表后断网**

  **操作步骤：** 联网查看国家和某国城市；关闭 App；断网重开；重新打开同一国家和城市列表

  **应看到的结果：** 手机此前保存的列表仍可使用；读取新列表失败不会清空已有列表；城市仍属于所选国家

- [ ] **L13 没有城市可选**

  **操作步骤：** 使用已确认没有城市的测试国家；打开城市列表

  **应看到的结果：** 提示该国家或地区暂无可选城市；与搜索不到城市、读取失败的提示有所区别；不出现其他国家的旧城市

- [ ] **L14 等待期间更换国家或离开**

  **操作步骤：** 在网络较慢时打开甲国城市列表；立即改选乙国，或关闭页面；等待后再查看

  **应看到的结果：** 甲国较晚出现的结果不会显示到乙国列表，也不会在关闭页面后突然改变已保存内容

- [ ] **L15 新列表到达时保留输入**

  **操作步骤：** 请开发准备已有旧列表、稍后取得新列表的情况；在等待时输入搜索文字；等待列表更新

  **应看到的结果：** 搜索文字保留，并按新列表显示匹配项；已选的国家或城市不被自动换成其他项目；时区和经纬度不因列表刷新而被重填


## 5. 国家、城市、时区和经纬度之间的联动

- [ ] **R01 城市自动填写**

  **操作步骤：** 记录打开页面时的时区；选择国家和一个城市；查看时区、纬度、经度

  **应看到的结果：** 三项都变为选中城市提供的值；当地时间按该时区显示。城市给出的位置是城市参考位置，不要求等于手机此刻的位置

- [ ] **R02 更换城市覆盖手工内容**

  **操作步骤：** 选城市甲；手工换一个时区并修改两项经纬度；再选择同一国家的城市乙

  **应看到的结果：** 城市、时区、纬度、经度一起更新到乙的值，不混用甲或手工填写的旧值

- [ ] **R03 重选同一个城市**

  **操作步骤：** 选城市甲；手工改时区和经纬度；重新打开城市列表，再选甲

  **应看到的结果：** 手工填写的时区和经纬度保持不变，不被同一个城市再次覆盖

- [ ] **R04 更换国家清除刚带出的值**

  **操作步骤：** 在本次页面中选城市甲，不手工改时区或经纬度；再改选另一个国家

  **应看到的结果：** 城市清空；甲自动带出的经纬度清空；时区回到打开页面时的值。若打开页面时没有时区，显示 `Unknown`，不保留甲的时区

- [ ] **R05 更换国家保留手工值**

  **操作步骤：** 选城市；手工改时区和两项经纬度；改选另一个国家

  **应看到的结果：** 城市清空，但手工时区及经纬度保留

- [ ] **R06 只改过一项经纬度**

  **操作步骤：** 选城市；只修改纬度，不修改经度；再更换国家；交换纬度和经度重复一次

  **应看到的结果：** 手工修改的那一项保留，仍由城市自动带出的另一项清空；两项不会被一并清除或一并保留

- [ ] **R07 只点输入框不算手工修改**

  **操作步骤：** 选城市；依次点纬度、经度输入框，不改任何文字；再更换国家

  **应看到的结果：** 仍按城市自动带出的值处理，两项经纬度清空；仅点击输入框不会改变这条规则

- [ ] **R08 重选同一个国家**

  **操作步骤：** 选国家、城市并修改时区或经纬度；再次选择同一个国家

  **应看到的结果：** 城市、时区、经纬度都保持原样

- [ ] **R09 重新编辑已保存的位置**

  **操作步骤：** 保存一个完整 Site；重新进入编辑页，先不选新城市，直接更换国家

  **应看到的结果：** 城市清空；重新打开页面时已有的时区和经纬度保留；再选择新城市后，才按新城市重填

- [ ] **R10 新城市资料不能使用**

  **操作步骤：** 请开发准备一个无法使用其时区或位置资料的城市；先选一个正常城市，再尝试选这个城市

  **应看到的结果：** 提示无法使用该城市资料；原城市、时区、经纬度保持原样，不出现只换了一半的情况

## 10. Gateway 页面与更新时间

本节中可以执行的项目，Wi-Fi 网关和 4G 网关分别执行。进入的是网关详情主页面，不是只显示设备资料的子页面。

  **应看到的结果：** 两行时间都按 Site 时区显示并继续走动；差值与两者差异相符。`Local` 指按 Site 时区显示的当前时间，不是直接照搬手机时区

- [ ] **G09 更新期间断开或离开**

  **操作步骤：** 开始更新时间后立即离开页面，或关闭蓝牙；随后重新进入并连接

  **应看到的结果：** 不在别的页面弹出此次成功结果；重新连接后重新读取网关状态，不一直显示上次的等待状态，也不直接沿用上次未完成的成功判断

- [ ] **G10 时间资料已过时且手机断网**

  **操作步骤：** Site 使用已识别的时区，但资料已到切换时间；手机断网，保持与网关蓝牙连接；点 `Sync clock`

  **应看到的结果：** 提示需要刷新时间资料，不显示更新成功；不能直接改用手机时区给这个 Site 的网关更新时间；恢复网络取得资料后可重试

- [ ] **G11 手机断网但有有效资料**

  **操作步骤：** 联网取得 Site 当前时间资料；断网但保留蓝牙；在资料仍有效时连接网关，点 `Sync clock`

  **应看到的结果：** 可按已有有效资料尝试蓝牙更新时间；成功与否以网关实际回复及重新读取结果为准，不因手机断网就错误声称已完成远程更新

- [ ] **G12 编辑 Site 后重新查看网关**

  **操作步骤：** 在编辑页把 Site 时区从甲改为乙并确认；再打开所属网关详情并连接

  **应看到的结果：** 显示乙的时区和夏令时资料；按网关实际时间判断是否还需要更新；不能把刚显示的新 Site 时区当作网关已经采用新时区的证据

- [ ] **G13 部分网关没有完成更新**

  **操作步骤：** 同一 Site 放两台网关，让一台可完成更新、另一台暂时不能完成；修改 Site 时区并确认；查看结果后分别进入两台网关

  **应看到的结果：** 能区分已完成和未完成的网关；一台成功不代表两台成功；恢复另一台后可以继续处理；其他 Site 的网关不受影响

- [ ] **G14 旧 Site 没有可用时区**

  **操作步骤：** 使用未设置时区的旧 Site；手机时区设为明确值；连接网关并更新时间；再为 Site 设置有效时区重试

  **应看到的结果：** 未设置 Site 时区时，时间按手机时区处理；不虚构 Site 夏令时资料，也不自动把手机时区保存进 Site。设置有效 Site 时区并取得资料后，改用 Site 时区


## 11. 完整操作与页面显示检查

- [ ] **A01 创建到网关的完整操作**

  **操作步骤：** 新建 Site → 选择国家和城市 → 手工调整经纬度 → 选择有夏令时资料的时区 → 创建 → 重新编辑核对 → 使用该 Site 的测试网关并连接 → 更新时间 → 退出重进

  **应看到的结果：** 各页使用同一个 Site 的内容；手工经纬度不丢；时区、夏令时显示一致；App 保存结果与网关实际更新结果均有记录

- [ ] **A02 无网关的 Site**

  **操作步骤：** 在无网关 Site 中改时区并保存，查看结果；按页面说明进入其各个 Space 并连接测试设备

  **应看到的结果：** 保存结果明确没有网关需要更新，不一直等待不存在的网关。各 Space 设备是否真正采用新的时间，需逐个检查；仅查看夏令时说明不算设备已更新

- [ ] **A03 夏令时切换后的实际设备表现**

  **操作步骤：** 使用准备好的切换测试条件；完成 Site 和网关更新时间；由设备测试人员观察切换前后设备时间及一条测试用定时开灯任务

  **应看到的结果：** 分别记录 App 显示、网关时间、设备时间、灯的实际执行时间；只有四者都与准备好的时间安排一致，才能判定这条完整操作通过。此项需要真实设备及相关团队配合

- [ ] **A04 中英文和长名称**

  **操作步骤：** 将 App 分别设为中文、英文；选择名称较长的国家、城市和时区；展开夏令时说明；在网关页查看

  **应看到的结果：** 标题、提示、按钮和说明能读完整，不显示内部文字代号；有中文名称时优先显示中文，未提供中文名称时可显示英文；不能把国家或城市换成另一个项目

- [ ] **A05 小屏幕、键盘和大字体**

  **操作步骤：** 在小屏手机上打开国家、城市搜索；输入经纬度并触发错误；展开夏令时说明；再用较大的系统字体检查

  **应看到的结果：** 可滚动看到输入位置、搜索结果和错误提示；键盘不会使当前输入内容无法查看；收起键盘后可点保存；文字、箭头和状态标签不重叠、不被截断

- [ ] **A06 连续操作与重新打开**

  **操作步骤：** 连续更换国家、城市和时区，多次展开收起说明；保存后重开 App，再进入编辑和网关详情

  **应看到的结果：** 不闪退、不出现重复列表或大块空白；最终保存的是最后确认的内容；页面不会在等待后跳回更早的选择


## 12. 时间有限时先执行这些项目

2. `R02`、`R04`、`R05`、`R09`：城市和国家变化时，检查时区、经纬度该替换还是该保留。

8. `A01`：从创建到网关的完整操作；实际夏令时切换验收再执行 `A03`。
