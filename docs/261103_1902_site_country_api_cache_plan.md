# Create / Edit Site 国家接口与缓存方案

日期：2026-11-03。状态：已实施并完成自动化验证；未提交，真实接口与 UI 待人工验收。

建议复用现有 Create / Edit 共用表单和搜索组件，用一个进程级国家目录服务管理服务器数据、内存快照与持久缓存。每次进程首次进入表单时自动刷新一次；有缓存先展示，失败保留缓存；无缓存且请求失败时，每次明确点击国家输入框可重试一次，成功后才可选择。

## 2. 方案比较与建议

| 方案 | 优点与代价 | 建议 |
| --- | --- | --- |
| 首次进入任一 Create/Edit 表单时刷新，共用服务 | 进入页面即开始准备；有缓存不等网络；无需在启动链路增加请求；首次无缓存需等待 | 已确认 |
| App 启动时刷新，共用服务 | 首次进入表单前可能已加载完成；不使用表单也请求，启动时离线仍需等用户在无缓存状态下点击重试 | 若要求每次启动无论是否使用都请求，可选此项 |

两种触发方式采用相同缓存和次数控制。将状态放在页面实例中会使 Create/Edit、退出重进重复请求，不满足要求。

缓存建议使用独立 JSON 文件和内存快照。现有设备配置缓存存入账号所属 SQLite，页面会在多个时机请求，不适合直接承担公共国家目录。沿用项目已有 Codable 与原子文件写入做法；新增范围限定为国家目录服务，不建通用缓存框架，不改数据库版本。

## 3. 接口与数据约定

1. 在 `NetowrkReqeustApi` 增加国家列表请求，复用 `NetworkRequest`。方法 `POST`，路径 `/sitespace/common/countries`，无业务参数、无请求正文；`/srv2` 继续由现有 baseURL 提供。
2. 发起请求时固定当时的 `ServerRegion`，请求构造和后续执行使用同一分区。各分区结果共用一个国家缓存，账号/分区切换不额外请求。品牌已有请求头规则继续沿用。
3. 使用现有 10 秒超时配置，并复用已有总时限请求入口使等待有界；不沿用示例中的无限超时，也不关闭 TLS 证书校验。不增加自动重试或备用服务器请求。
4. 接口适配层要求 HTTP 成功、业务 `code == 200`、`data` 为非空数组。通用网络层还支持其他成功格式，国家解析层仍按本接口契约单独校验，避免空对象误当有效目录。
5. `code` 是唯一身份，必须是两位 ASCII 大写字母且无重复；不按国家名称反推代码，不将 249 或现有代码集合写成运行时白名单。
6. `names_json` 映射到现有多语言名称结构。英文名称优先非空 `names_json.en`，其次非空 `name`；中文优先非空 `names_json.zh-Hans`，缺失时回退英文。`names_json` 缺失或 null 可按 `name` 回退；字段类型错误或没有可用英文名称则整批拒绝。无效项不静默丢弃后覆盖缓存。
7. 保持现有英文名称排序，中英文名称及完整国家代码搜索，忽略大小写、宽度和变音符号。`name` 与本地化名称不同时也可作为搜索别名；提交值始终是代码。
8. 接口数据包含全部语言名称，切换显示语言只重新取展示名称，不消耗另一次请求。

## 4. 自动刷新与无缓存重试的边界

### 生命周期

首次进入 Create/Edit 自动刷新一次；用户补充允许的例外是：尚未成功且没有可用缓存时，每次点击国家输入框可以重试。生命周期仍指进程启动到终止，前后台切换不算新生命周期。

- 共享服务维护 `notStarted → loadingCache → requesting → succeeded / failed`，在调用网络前进入 requesting；多个页面或连续点击共用同一在途请求。
- `startIfNeeded()` 只负责首次初始化和自动刷新，不因页面重建、网络恢复或回前台而自动重试；`retryIfUnavailable()` 仅在 `phase == failed && catalog == nil` 时发起下一次请求。
- 首次异步读取磁盘快照，后续明确重试不重复加载磁盘；读写/解码在串行后台队列完成，状态及 UI 在主线程更新。缓存损坏视为无有效缓存。
- 请求由服务持有，离页只解除页面订阅，不取消共享请求；成功后仍更新缓存，回到页面可使用结果。
- 已有有效缓存时，即使刷新失败，点击也只使用缓存；本轮成功后（包括落盘失败但内存可用）也不再请求。
- 无缓存失败时，首次聚焦、已聚焦状态再次点击文字区域、图标或边缘均可以重试。键盘输入、清空搜索词、程序刷新列表和恢复前台不触发重试；重试开始后仍保留已有 query/selection。
- 每轮请求分配独立身份。旧请求超时后的迟到成功/失败或重复回调不能完成新请求、更新缓存或改变其状态。
- App 真正重启后重新获得一次自动刷新机会；无缓存失败的用户不需要为了重试而重启。

### 持久化

- 建议位置：App 沙盒 `Library/Application Support/CountryCatalog/countries-v1.json`，不放入账号目录；不同品牌按各自 App 沙盒隔离。该缓存不参加 Site 云端同步、分享或导出，并沿用项目本地缓存排除备份的方式。
- 文件包含本地 schemaVersion、最近成功获取时间及完整国家数据；时间用于诊断，不作为禁止使用旧缓存的 TTL。缓存长期可用，直到有效响应完整替换或文件不可读。
- 只有整批校验成功才替换内存目录并原子写入磁盘。网络错误、业务错误、空数组、重复/非法代码或解析失败都不删除或覆盖旧缓存。
- 磁盘文件缺失、损坏或版本不支持视为无可用缓存；仍执行首次自动请求；失败后允许明确点击重试。没有任何 bundle、系统国家名单或旧 JSON 的兜底，也不以旧文件预填网络缓存。
- 网络成功但磁盘写入失败时，本次进程仍可使用新内存目录，磁盘旧文件保持原样；下一次启动按实际磁盘情况处理，不为了落盘失败再次请求。必要诊断仅在 DEBUG 输出，不输出敏感请求内容。

### 可见行为

| 缓存 / 刷新状态 | 国家列表与选择 |
| --- | --- |
| 有有效缓存，请求进行中 | 立即可搜索和选择缓存中的国家，后台刷新 |
| 有有效缓存，请求失败 | 继续使用缓存；不弹出阻断错误 |
| 无有效缓存，请求进行中 | 可展开搜索区域，显示 `Loading…`；无可选择项，输入搜索词不触发额外请求 |
| 无有效缓存，请求成功且数据有效 | 展示结果，并按当前仍有效的搜索词过滤 |
| 无有效缓存，请求失败 | 显示国家专用失败提示，无可选择项；每次点击输入框可重新请求一次，在途点击不重复发起 |
| 新进程启动后首次使用 | 读取上次缓存，再执行新的一次刷新 |

无缓存失败文案建议：英文 `Unable to load countries. Tap the country field to try again.`；简体中文 `无法加载国家列表，请点击国家输入框重试。` 独立国际化 Key，不修改城市仍可重试的通用失败提示。

## 5. 表单、搜索与已有数据的一致性

- `SiteFormViewController` 统一订阅服务、获取目录并连接国家 loadOptions，移除当前依赖 bundle 已加载的入口拦截。国家选择仍仅由点击有效列表项提交，输入文本、取消或接口返回都不能修改草稿。
- 用户调整：成功且有效的响应全量替换目录，旧国家不合并保留。正在展开的列表也按当前搜索词重新计算，并使旧展示 ticket 失效；点击必须属于当前目录和当前展示，避免刷新后仍选到已删除国家。失败仍按已确认要求保留缓存；已有 Site 的持久字段不做批量删除。
- 下一次展开使用最新目录；已收起的国家名称可随有效刷新更新。新增“仅更新同一 selectedID 的标题”能力，不调用会清空搜索、关闭面板和取消请求的 `replaceSelection` 来刷新标题。
- 标题刷新前重新核对当前 selectedID、页面账号/分区、编辑权限、页面可见及提交状态；离页、后台或正在提交时只更新服务。重新可见/恢复 active 时读取现有快照补齐标题，不触发新请求。显示更新不得用回调开始时捕获的旧国家覆盖用户刚选的新国家。
- 保留现有 search ticket 防止快速输入、A→B→A、取消和重新展开后的旧结果回填；页面销毁解除订阅，服务不强持有页面。
- Edit Site 没有缓存时先显示原国家代码/原历史字符串；刷新匹配成功后只更新名称。服务器删除某个代码、旧数据包含自由文本或未识别代码时，保留原值及其显示，允许其他字段按原规则保存。旧值不自动加入新国家候选列表。
- 刷新目录、名称变化或目录缺少已选代码，不自动清空城市、坐标或时区。用户明确选择不同国家时才复用 `SiteFormDraft.selectCountry`：清空城市及城市派生的值，保留手动/GPS 输入，按现有来源规则恢复时区。选择同一个国家不重置联动值。
- 当前城市目录继续本地读取。以后服务器增加国家但本地城市 manifest 没有该分区时，国家仍可选，城市显示现有“暂无可选城市”。需区分“manifest 不含该国家”和“manifest 声明存在但文件缺失/损坏”；后者仍报加载失败，不能掩盖资源错误。国家接口失败不阻断已有国家对应的本地城市操作。
- 本次不变更国家必填性、Site 保存协议、SQLite schema、props 更新权限、导入导出、时区同步、SDK、固件或服务器实现。
