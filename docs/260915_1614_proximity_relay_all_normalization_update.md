# 邻近照明数量统一规范为 ALL

## 最新规则

按用户要求，`SpaceConfigurationIntegrityPolicy.normalizedProximityLightingNumber` 将所有大于 `20` 的非负整数统一为 `255（ALL）`，不再只兼容 `21`。

| 输入 | 结果 |
| --- | --- |
| 整数 0…20 | 保留原值 |
| 整数 21…254、255、256 及更大值 | 255 |
| 负数、小数、字符串、布尔、null、非有限数值 | 校验失败 |

## 实现范围

- 统一入口先判断数值类型、整数和非负条件，再判断是否大于 20；先规范化再转换为 UInt8，支持 JSON 中大于 UInt8/Int64 上限的正整数。
- Profile 校验、配置比较、导入预检、云端赋值、本地 SQLite 读取及 Profile 模型沿用同一规则。配置序列化同时处理历史持久化基线中的原始值，双向比较和回读诊断保持一致。
- 普通 Profile 中保留的闲置数量字段也统一规范化，防止它阻碍完整 Space 清理或与模型快照不一致。
- 设备观察缓存、路径、区域、时间参数等字段保持既有语义；真实配置差异仍正常参与同步。
- 不更改 SDK、依赖、本地化或 target 配置。本轮真机继续由用户手动验证。

## 验证

- 数量边界回归通过：遍历 `21...255`，并覆盖 `256`、`65535`、`Int64.max`、`UInt64.max` 的 JSON、预检、清理及配置比较；`0...20` 保持原值，错误类型和负数、小数继续拒绝。
- 真实云端样本通过：500 台设备、1 项数量规范化、0 个邻近照明同步任务，其余字段保持一致。
- Profile 7/8 真实 SQLite 回归通过：大整数读取为 255，读取不直接修改数据库，后续保存写入 255；其他字段保留。
- 历史基线双向比较、导入保护解除、上传回读及恢复记录回归通过。
- SunSmart Debug / iphoneos / generic/platform=iOS / CODE_SIGNING_ALLOWED=NO 直接 `xcodebuild` 构建通过；未使用 Simulator。
