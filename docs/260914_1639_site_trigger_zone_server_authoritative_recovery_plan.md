# Site Trigger Zone：以服务器目标恢复展示与设备同步的修复方案

日期：2026-09-14。状态：供确认的分析与实施方案；本轮未修改业务代码、云端数据或设备配置。

## 判断

方向总体合理：已完成且可验证的服务器 `extensionData` 应作为 **Site Zone 配置目标**；本地未确认 `pending.target` 不能在无法对应时反向覆盖服务器。页面应展示服务器 Zone，不应因为单个成员的旧字段或同步冲突把所有卡片替换成“空间信息不可用”。设备最终目标则必须由完整 Site/Space/Group 邻近照明拓扑计算，再和本机可验证的 Node 观测状态比较。

但“服务器优先 + 比较本地 nodes”还不足以安全生成全部删除、更新、新增任务：Node 本地字段是缓存，不等于设备已执行的真实状态；已删除 Zone 的旧成员可能不在新服务器对象中；只比较当前 Site Zone 会误删 Group Path、Group Trigger Zone 或 Space Trigger Zone 仍需要的邻居。丢 ACK、旧任务未完成、地址复用、Primary Key/Bind/转发 Key/TTL 未知时，必须保留待核实或阻断状态。当前 `SiteTriggerZoneSyncPlanningPolicy` 只是**旧/新完整目标的只读差异预览**，还没有设备读回、发送器、持久逐任务回执。

这会改变此前“保留本地 4-Zone 目标并安全合并”的既定策略：若本地目标确实无法与新云端对应，改为云端目标有效，本地目标仅作为可审查的恢复快照，绝不自动 POST。当前用户响应的 Site 级对象有 2 个 Zone；页面曾有更多本地 Zone，数量不能凭云端响应推断为设备已同步或安全删除。

## 建议的状态与数据边界

1. **服务器可采纳条件。** `get/siteprops` 业务成功、Site 身份一致、`extensionData` 是完整且可解析的对象、Zone ID 唯一、成员身份可保留、响应版本不比已采纳版本旧。同一时间戳但内容不同也应标记歧义。缺字段、空字符串或权限不明时不覆盖有效缓存，保留最近一次已确认快照供只读展示并标记过期；未来 schema 可以保留、显示服务器原始摘要，但不能按旧 schema 编辑或下发设备任务，也不能继续上传旧本地目标。POST 回显不作为云确认；仍以随后 GET 为准。当前接口缺 CAS，并发编辑仍按已约定的串行操作约束处理。
2. **旧成员兼容。** `triggerElementAddress` 作为旧格式的触发来源地址保留；不能直接当成规范化 `deviceAddress`。用 `(spaceId,nodeUUID)` 匹配当前 Node，核实 Space、Group、主地址、元素地址及 Vendor Model 后推导规范化地址。能确认的成员形成可编辑投影；无法确认的成员仍显示原始身份与所在 Space，但该 Zone 的写入和设备任务暂停，不丢成员、不猜地址、不静默转换。未知字段原样保留，序列化完整对象时核对未编辑部分不变。
3. **云端接管本地 pending。** 先在本机持久保存原 `base/target/operationId` 与已确认的设备同步证据；将无法合并的 pending 从活跃上传队列隔离。事务内把 `data/serverData` 指向已验证云端版本，清掉活跃冲突与旧提交令牌，并用版本指纹阻止迟到的旧 POST/GET/ACK 重启旧目标。归档仅供人工查看或手动重新编辑，不自动重新提交。尚未点击 Save 的页面草稿仍按已确认规则只留在当前进程；若基线已变，将草稿标记过期并提示重新基于服务器版本编辑，不把旧草稿当作新的 Save 目标。
4. **设备目标与观测分离。** 目标用全部服务器 Site Zones 加当前 Group Path、Group Trigger Zone、Space Trigger Zone，以及 Space 级 Primary Key 规则计算；按 `(spaceId,nodeUUID)` 关联 Node，地址只是可重新验证的现场快照。观测汇总本地 Node 缓存、已持久化的逐任务 ACK/目标版本和可用的设备读回；缺少可信证据时是 `unknown`，不是“已同步”。历史已确认云端成员与设备回执只用于发现旧关系和补充核查，未云确认的本地草稿不等于已部署关系。
5. **任务分类。** 目标新增关系生成 `Configuration`（界面可标 Add）；目标参数改变生成 `Configuration`（Update）；目标不再需要的邻居生成 `Remove`（Delete）。同一设备同时有旧邻居清理和新终态时先 Remove 后 Configuration；Remove 只清过时边，最终终态保留其他 Path/Zone 的贡献。Zone 从服务器消失时仍枚举受影响的旧 Node；没有旧快照或设备读回时列为待核实，不发清空命令。Key/Bind、转发 AppKey、TTL、Enable、Relay、邻居等前置与终态都进入比较。任务按 Space 排序、版本化持久化，并区分待执行、成功、失败、未知、阻断；旧版本回执不能确认新目标。

## 页面与操作

- 把“可展示”“可选中”“可编辑”“可执行设备同步”拆成独立条件。对可解析的服务器 Zone 按 Zone/Space/设备显示；成员资料不全时仅对应 Zone 或成员标记问题，其他 Zone 正常显示。当前全局 `supportsMemberEditing` 不应直接决定所有卡片的结构。
- 选中 Zone 后始终展示 `Test / Reset / Delete / Save` 操作区，按钮是否可用按各自动作判断。`Reset` 仅恢复当前未保存草稿到已确认服务器基线；`Save` 只在版本、权限、成员与完整对象写入条件均满足时可用；删除需另有旧设备清理计划。当前正式版 `Test` 分支没有实现且按钮恒禁用，因此第一步保持**可见但禁用**，不把展示按钮误当成功能已交付。
- 云端保存与设备同步分别显示状态。云端已确认而设备尚未读回/执行时保留待同步入口；有缺失 Space、权限或拓扑证据时展示可定位原因，不把所有情况写成“空间信息不可用”。UI 初始零宽/零高约束冲突另行修复并在实际设备复测。

## 实施与验收顺序

1. **只读诊断与契约用例：** 记录本次 `state.data/serverData/pending` 的 Zone 数、版本和布尔状态，不记录密钥；用脱敏响应覆盖旧 `triggerElementAddress`、空 Zone、混合字段、缺失 Node、未来 schema、相同/更旧时间戳。
2. **兼容解析与云端接管：** 建立显示投影、按 Zone 校验、pending 归档/替换事务及迟到响应隔离；测试“本地 3/4 Zone、服务器 2 Zone”的失配，验证不自动上传旧目标、不丢未知字段或设备清理证据。
3. **只读任务重算：** 以服务器目标和完整拓扑算期望，再和观测状态比较，覆盖新增、删除、参数改变、共享邻居、Zone 删除、已确认成功/丢 ACK/缓存陈旧、跨 Space Primary 前置任务；缺证据只生成阻断/待核实任务，不发送设备命令。
4. **UI 与真机：** 解耦卡片和按钮可见性/可用性；用 `MtestiPhone15` 检查实际 Zone 数、多 Space、空/旧格式/失权卡片，中英文、长文案、选中操作栏和约束日志。最终交互仍需人工确认。
5. **设备执行阶段：** 沿用已确认的云先、按 Space `Remove → Configuration`、持久回执和重试方案；在先前约定的 3A 实物协议/过渡状态验证通过后才开放真实命令。改动涉及共享源码/文案/target 时核对所有引用 target，运行聚焦测试与 generic iPhoneOS 构建。

## 待确认的产品取舍

建议确认：当本地 pending 无法安全对应服务器时，服务器版本立即成为有效配置；旧 pending 只归档、不自动重传。操作按钮在选中时保持可见，尚未实现的正式版 `Test` 暂时禁用；真正启用 Test 另需定义测试命令和结果语义。
