# Space 缓存分阶段实施计划

## 目标

同一 Space 内重复切换 Group、Scene、Timed 时复用有效结果；首次显示的同步检查按主线程预算分片。保留日程 owner/cleanup、残留删除、保护状态及跨空间隔离语义。

## 阶段与验证

1. 扩展现有刷新器：Space 会话生命周期、完成结果保留、可取消的分片页面查询；用真实调度逻辑验证重入命中、版本失效、退出取消、Cell 复用。
2. Scene/Timed 卡片使用异步状态查询；页面仅在首次或发生变化时刷新；Group 成员状态使用共享上下文；移除生命周期中的全量诊断打印。验证新状态检查与原完整同步计划的布尔结果等价。
3. Space 持有未知 Scheduler 状态补读协调器，合并切页请求、分批读取、失败退避、会话退出丢弃迟到回调；保留 SDK 节点级完整性处理。
4. 复用传感器索引和批次应急控制器数据，记录缓存命中及查询时长。版本失效先使用现有保守机制，按字段的精细失效在有充分事件覆盖和真机指标后另行评估。
5. 运行针对性回归、iphoneos 构建，检查所有共享品牌 target 的 Sources 配置；使用 MtestiPhone15 做隔离的真实 Cell/调度验证。iPad LLH 的原数据复测与最终体验由人工完成。

## 边界

本轮不删除持久化缓存，不改变云导入和实际同步授权，不自动操作 iPad LLH，不使用 Simulator 或 Computer Use。SDK Model 级读取粒度属于后续优化；本轮复用现有 SDK API。

实施后另记实际变更、已验证指标、阻塞项与剩余步骤。

本轮实施和验证结果见 [Space 运行时缓存实施结果](260915_2104_space_runtime_cache_implementation.md)。
