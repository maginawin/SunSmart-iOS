## 2 协议概述
本协议基于 SIG Mesh 标准协议框架，针对特定应用场景进行扩展与定制，用于实现设备间安全、可靠、高效的通信。
适用于智能家居、智能照明、工业自动化等物联网领域，可支持数百甚至数千个设备组成的 Mesh 网络。

### 2.1 通信方向定义
- **下行通信**：外部发起与 SIG Mesh 设备通讯（如 网关端/App → 目标端）。
- **上行通信**：SIG Mesh 目标端主动上报或应答外部（目标端 → 网关端/App）。

### 2.2 字节序
本协议中的多字节数据为小端字节序（Little Endian）。

### 2.3 特殊符号约定
- `null`：表示**无此字段**（不占字节）。
- `---`：表示**字段存在但不处理**，发送端可填任意值，接收端无需解析。
- `...`：表示重复迭代（同类字段按上下文重复出现）。

### 2.4 数据类型

有关协议中数据类型，定义如下：

| 数据类型符号 | 数据类型描述 |
| --- | --- |
| U8 | 无符号8bit型数据 |
| S8 | 有符号8bit型数据 |
| U16 | 无符号16bit型数据 |
| S16 | 有符号16bit型数据 |
| U24 | 无符号24bit型数据 |
| U32 | 无符号32bit型数据 |
| S32 | 有符号32bit型数据 |
| U8[] | 无符号8bit型数组，数组长度由上下文确定 |
| U8[n] | 无符号8bit型数组，数组长度由n的大小确定 |
| U16[n] | 无符号16bit型数组，数组长度由n的大小确定 |



## 3 协议层级与扩展位置
SIG Mesh 标准协议架构分为四层：物理层、数据链路层、网络层和应用层。本私有协议基于标准协议进行扩展，主要在 Access/Model 层实现模型参数的设置、获取、控制与返回等功能。

## 4 协议定义
### 4.1 报文格式与字段顺序

| 字段名称 | Vendor Opcode | 操作码 | 操作子码 | 数据内容 |
| --- | --- | --- | --- | --- |
| 字段长度 | 3字节 | 1字节 | 1字节 | 若干 |
| 字段描述 | 协议类别 | 绑定对象 | 绑定对象的属性 | 数据内容 |

说明：
- Vendor Opcode（Mesh 3-byte opcode）由 **1 字节厂商操作码 + 2 字节 Company ID（小端）**组成。
  - 我司 Company ID 为 `0x0A78`（小端字节序为 `0x78 0x0A`）。
  - 使用 `BT_MESH_MODEL_OP_3(op, cid)` 生成，首字节为 `0xC0 | op`。
  - 示例：`op=0x30` → `0xF0`，组合为 **0xF00A78**。
- 本节“操作码/操作子码”指代码中的 `opcode/subcode`（均为 1 字节），不是 SIG Mesh vendor opcode。
